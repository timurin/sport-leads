# PC-UI-10/12 — UI-G: дашборд производственного календаря

**Статус:** UI-A–UI-H = OWNER-APPROVED; DESIGN-APPROVED = true, `2026-10-05`, по [решению владельца](../../../tasks/pc-02-1-lightweight-design-freeze-implementation-contract.md). Дизайн зафиксирован; реализация не начата. Проверки runtime/Edge, ранее не выполненные, остаются техническими проверками реализации.

## Назначение

UI-A остаётся основным недельным календарём. UI-G показывает сводку по участкам и ресурсам. Ближайший паттерн PT-02, токены SL-UI-BASE-v1; sidebar/topbar в HTML — статический контекст DS-SHELL-01/02. Детальный Гант одного заказа возможен как будущий drill-down из UI-C после отдельной проверки владельцем; утверждённый UI-C не изменён.

Шесть карточек участков имеют фиксированный состав, независимо от числа заказов. Каждая ресурсная строка показывает план, доступность, резерв и динамику по семи дням или четырём неделям. Выбор периода меняет начало дневного и недельного окна; фильтр участка оставляет одну карточку. Нажатие ресурсной даты раскрывает только назначения выбранного участка/даты, ресурсные итоги и таблицу по **8 строк на страницу**. Из деталей есть переходы в UI-D с параметрами `stage`/`date`, UI-E и UI-F; UI-A и UI-H доступны из шапки. Эти файлы имеют собственные демоснимки, межстраничной синхронизации нет.

## Нормативы и ресурсные границы

- Закупка — ручной milestone, без часовой нормы. Готовность не выводится из ТК/PO из-за открытого P1 `refresh-model`.
- Дизайн — явная синтетическая ручная оценка в человеко-часах, без умножения на тираж. Для части заказов оценка неизвестна.
- Подготовка печати — 1 человеко-час на заказ. Четыре плоттера — независимые очереди по 15 пм/машино-ч. Каландр — 60 пм/машино-ч, оператор отдельно в человеко-часах. Метраж в демоснимке задан **отдельно** от количества изделий; формула вывода метража из тиража не предполагается. Для каждого девятого заказа созданы две отдельные партии печати/каландра с собственными датами и объёмами.
- Раскрой: общий пул двух раскройщиков `qty / 20` чел.-ч для поштучного способа; лазер `qty / 100` машино-ч плюс столько же чел.-ч отдельного оператора. Партии одного заказа не удваивают количество изделий.
- Пошив: синтетический снимок `840 с/изделие` для одной швеи, `qty × 840 / 3600` чел.-ч; у части заказов обязательная норма отсутствует. Упаковка — одна бригада из двух, `qty / 80` часов **участка**, соответствующих `2 × qty / 80` человеко-часам; пропускная способность не умножается на два повторно.
- Для буднего дня показаны предварительные мощности ресурсного контракта при эффективности 100%; выходной — 0, ремонт плоттера 3 на 09.10 — 0. Нулевая мощность не даёт процента. Если хотя бы одно назначение ресурса имеет отсутствующую норму, известная часть плана показывается, но полная доля загрузки помечается «неизвестна»; 0% и фиктивный резерв не выводятся. Человеко-часы, машино-часы и часы бригады не складываются в общий процент участка. Перегрузка строго >100%, близко к пределу — 80–100%.

## Синтетические сценарии и границы

Переключатель создаёт детерминированные сценарии 5/30/50/100 условных заказов в памяти страницы; сброс восстанавливает 5 заказов и исходные фильтры. Плановый старт заказов распределён по датам октября 2026; даты работ сохраняют очередность: закупка и дизайн параллельно → подготовка → плоттеры → каландр → раскрой → пошив → упаковка. План можно размещать до фактической готовности, но прототип не запускает операции и не доказывает готовность материалов. Синтетические даты/метраж/нормы не являются кадровыми или производственными данными MOSMADE.

Визуальное решение владельца по UI-G принято 2026-10-05. Проверены JS-синтаксис, расчёты и ограниченный вывод при 5/30/50/100 заказах, локальные ссылки и структура HTML. Повторная проверка Edge 1440/1280/768/390/320 px, клавиатуры и фактического переполнения в текущей ревизии ожидается при доступном браузере; прежние скриншоты относятся к старой версии Ганта и не подтверждают эту компоновку.
