# PC-UI-11/12 — UI-H: центр отклонений

**Статус:** UI-A–UI-H = OWNER-APPROVED; DESIGN-APPROVED = true, `2026-10-05`, по [решению владельца](../../../tasks/pc-02-1-lightweight-design-freeze-implementation-contract.md). Дизайн зафиксирован; реализация не начата. Проверки runtime/Edge, ранее не выполненные, остаются техническими проверками реализации.

## Компоновка и счётчики

UI-H использует PT-02, токены SL-UI-BASE-v1 и статический контекст AppShell. Верхние KPI считают **уникальные затронутые заказы**, **сигналы** и уровни `hard`/`risk`/`unknown` по полному синтетическому сценарию. Фильтры не меняют эти исходные итоги. Шесть компактных групп причин — перегрузка/пересечения, недоступность, материалы, зависимости, срок, неизвестные нормы — показывают число случаев и число уникальных заказов по полному сценарию и число видимых случаев по фильтру. При выборе группы открывается таблица по 8 случаев на страницу; поиск по номеру, период, участок, причина, критичность и сортировка по дате комбинируются. Пустой фильтр не удаляет исходные события.

Общий конфликт одного плоттера на одну дату с несколькими назначениями — **один случай** с массивом всех затронутых номеров. Детальная панель по запросу показывает уровень, участок, ресурс, дату, основание, источник, влияние и полный список заказов в ограниченной прокручиваемой области. Слияние не теряет участников; счётчик заказов не равен счётчику сигналов. Desktop и mobile содержат те же сведения, таблица на узком экране прокручивается внутри панели.

## Сигналы и действия

- Перегрузка рассчитывается отдельно для каждого ресурса/даты и только при известной ненулевой мощности. Общий ручной пул, лазер, его оператор, четыре плоттера, каландр и оператор, швеи и бригада упаковки не смешиваются в одну долю.
- Нерабочий день и ремонт плоттера дают `0` мощности и отдельную причину недоступности без процента. В сценарии ремонт плоттера 3 приходится на 09.10.2026.
- Пересечение плоттера опирается на **явное синтетическое** общее окно 09:00–13:00. Кнопка пробует перенести одну партию на другой плоттер только при свободном окне и достаточной мощности; иначе оставляет план и объясняет причину. После удачного локального переноса весь реестр пересчитывается, остальные конфликты сохраняются.
- Отсутствие ручного подтверждения закупки и неизвестные оценки дизайна/пошива не заменяются значением 0 и не исчезают от кнопки «Запросить данные». Подготовку до готовности материалов можно планировать, запускать нельзя; при демостатусе запуска это `hard`, иначе `risk`. Прогноз срока сравнивает дату упаковки со сроком, не объявляет факт просрочки.
- «Отметить просмотренным» меняет только локальную отметку и оставляет сигнал открытым. Ссылки ведут к UI-G, UI-E, UI-F или UI-C по контексту. Никаких изменений ERP, API или серверных прав прототип не делает.

## Масштаб и границы

Переключатель 5/30/50/100 заказов пересоздаёт детерминированный синтетический снимок; сброс удаляет отметки и возвращает фильтры. Назначения используют те же предварительные нормы и календарные мощности, что UI-G; частичные партии имеют отдельные количества, метры, даты плоттера/каландра. Объединение конфликтов выполняется по `resource + date`; список участников хранится у каждого случая. Пагинация ограничивает высоту реестра при 100 заказах. UI-H не утверждает интеграцию с ERP; факт читается из ТК, а неподтверждённые окна смен, материалы и норма дизайна сохраняют unknown до реальной настройки, P1 `refresh-model` не закрыт.

Визуальное решение владельца по UI-H принято 2026-10-05. Проверены JS-синтаксис, группы, поиск/фильтрация, 5/30/50/100 заказов, агрегирование нескольких заказов в один конфликт и ограничение таблицы 8 строками. Повторная проверка Edge 1440/1280/768/390/320 px, клавиатуры и фактического переполнения в текущей ревизии ожидается при доступном браузере; прежние скриншоты относятся к старому списку карточек.
