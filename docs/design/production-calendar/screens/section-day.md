# PC-UI-07 — UI-D: участок за день

**Статус:** UI-A–UI-H = OWNER-APPROVED; DESIGN-APPROVED = true, `2026-10-05`, по [решению владельца](../../../tasks/pc-02-1-lightweight-design-freeze-implementation-contract.md). Дизайн зафиксирован; реализация не начата. Проверки runtime/Edge, ранее не выполненные, остаются техническими проверками реализации.

## Назначение и переходы

Выбор ячейки в [UI-A](../weekly-board-prototype.html) открывает `section-day-prototype.html?stage=<id>&date=YYYY-MM-DD&week=YYYY-MM-DD`. В UI-D дата и участок задаются URL, стрелками и селектором; `week` вычисляется из выбранной даты и обновляется при переходе через границу недели. «К календарю» возвращает в понедельник выбранной недели с фильтром участка. «Подробнее» открывает read-only операцию; ссылка на [UI-C](../production-order-prototype.html) передаёт обратную ссылку с `date`, `stage`, `week` на этот день. Для задания КД-041 она соответствует демокарточке UI-C; у прочих заданий ссылка прямо подписана «Открыть демонстрационный пример КД-041», без ложной связи. «Распределить / Перенести» предлагает открыть [отдельный демоплан КД-041 UI-E](../manual-scheduling-prototype.html) с возвратом на этот день; назначение из UI-D не меняется.

Неверная календарная дата и неизвестный участок при прямом открытии UI-D заменяются демозначениями 7 октября 2026 и «Пошив»; URL после отрисовки показывает нормализованный контекст. UI-A принимает `week` только для действительного понедельника и `stage` только из списка участков; иначе показывает демо-неделю или все участки. UI-C принимает `return` только на локальный файл UI-D с действительными и согласованными `date`/`stage`/`week`, иначе ссылка ведёт к UI-A. Это проверка навигации прототипа, а не обещание серверного маршрута.

## Данные и расчёт

| Поле | Источник в прототипе |
|---|---|
| Дата, участок | Query string / локальное переключение; будущий `GET /days/{date}?stage_id=` PC-02. |
| № группы, ТК, изделие, модель, вариант, плановое количество и календарный статус | Локальные снимки назначений UI-A; не CRM-заказ и не факт ТК. |
| Норма пошива | Снимок применимых строк выбранного варианта: `Σ(duration_seconds × multiplicity)` секунд на одно изделие одной швеи. |
| Трудоёмкость задания | Норма × количество **на выбранный день** / 3600, человеко-часы. По участку складываются человеко-часы заданий, не штуки разных моделей. |
| Доступная мощность | Демоконфигурация `DEMO_CAPACITY`: сотрудники в смену × часы смены × число смен × эффективность; рабочие дни пн–пт, датированные исключения. Эффективность по умолчанию `1` (100%). |
| Прочие участки | Для дизайна/печати/раскроя/упаковки трудоёмкость существует только как **ручная оценка демо**, без вымышленной нормы модели. Закупка — ручная готовность материалов без часов и процента. |

На 7 октября пошив КД-033: `(360 с × 1 + 240 с × 2) × 250 / 3600 = 58,33 ч`; мощность `5 × 8 × 1 × 100% = 40 ч`; загрузка `145,8%`, превышение `18,33 ч`. Сценарий `100%` использует два разных задания: `100 × 840 с / 3600 = 23,33 ч` и `100 × 600 с / 3600 = 16,67 ч`, всего `40 ч`; количества разных моделей не суммируются в KPI.

Неизвестная норма даже одного задания делает **общий процент неизвестным**: показываются известная часть и сообщение «Загрузка полностью не рассчитана». При нулевой мощности и в выходной деления нет. Блокировка запуска предшественниками показана отдельно от перегрузки и не отменяет плановое назначение. Демо-статус закупки не подтверждает закупку по ТК, складу или заказу поставщику.

## Компоненты и состояния

Заголовок, навигация дня, выбор участка, девять демосценариев, четыре KPI, список операций и панель «Мощность и ограничения». На desktop/laptop операции в плотной таблице PT-02; на tablet/mobile — карточки с теми же полями. Почасового графика нет: человеко-часы нескольких исполнителей не означают столько же часов настенного времени. Диалог не содержит действий запуска или записи, закрывается кнопкой/Escape и возвращает фокус.

Сценарии: резерв, ровно 100%, перегрузка, блокировка при свободной мощности, отсутствующая норма, нулевой штат, выходной с назначением, пустой день и закупка. Календарные статусы, причины блокировки и состояние мощности не объединяются в одно поле. Число операций — количество назначений, не процент изготовления.
