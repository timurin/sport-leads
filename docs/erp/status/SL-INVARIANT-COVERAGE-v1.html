Вывод

На записи защищены identity/shape, выбранная ONE OF ветка, замороженный коэффициент объёма, формулы Demand, физическая identity машины и автоматическая замена защищённых планов. PC-05.1B закрывает запуск планируемой операции без сохранённой привязки. Однако наличие assignment не доказывает соответствие текущему Demand, а lifecycle audit фиксирует удаление/отвязку, но не запрещает её.

PC-05.2 подтвердил P0 потери started facts на route reapply. IC-G01 (2026-10-11) устраняет этот proven path: preflight отклоняет destructive изменения, identical/future-only reapply сохраняет идентичность, факт, план и аудит. Подтверждены P1: manual delete снимал план с начатой операции (IC-G02 теперь запрещает); date move и resource unit edit ранее оставляли несовместимые allocations (IC-G03 теперь отклоняет эти изменения); quantity import оставляет прежнюю сумму allocations и допускает start по старой привязке. Ещё один P1 воспроизведён только через legacy/DB corruption: частичный snapshot может планироваться, поскольку нет frozen completeness manifest. Это не доказательство наличия публичного API для удаления snapshot nodes.

Сам PC-05.2 не добавлял guards и не исправлял данные. Последующие выбранные IC-G01/IC-G02/IC-G03/IC-G04 добавляют защиту route reapply и saved-plan linkage; PC-05.6C добавляет IC-SC-06 fresh-preview scoped queue reorder. Матрица отражает регрессионные проверки. Текущие risk rows: P0=0/P1=0/P2=13/P3=29 (42 invariants). Ни один найденный P0/P1 не считается устранённым успешным прохождением теста, который доказывает существующее отсутствие guard. Общий PC-05 и переходы roadmap stage остаются открытыми.
