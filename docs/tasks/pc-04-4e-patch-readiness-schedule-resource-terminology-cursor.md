# 1. Перенести ошибки готовности в шапку modal

Сейчас блок:

`Готовность к планированию`

и ошибки вроде:

`Нет рабочего времени`

показываются внутри вкладки `Основное`.

Это плохо:
при переходе на `Мощность / Оборудование / График / Исключения`
пользователь перестаёт видеть проблему.

## Требование

Вынести readiness status в header модального окна операции.

Рекомендуемый вид:

`Требует настройки · Нет рабочего времени`

или:

`Готово к планированию`

Разместить под названием операции / рядом со статусом в верхней части modal,
выше tabs.

Если ошибок несколько:
- показать первую/главную;
- рядом `Ещё N`;
- по клику раскрыть компактный список.

Не делать большой красный блок.

Статус должен быть виден на любой вкладке.

---

# 2. Проверить ошибку `Нет рабочего времени`

Конкретный кейс:

Операция:
`Упаковка`

Связанный ресурс:
`Бригада упаковки`

На вкладке `График`:
- Пн–Пт отмечены как рабочие;
- строка `Часы` показывает `—`;
- readiness на вкладке `Основное` показывает:
  `Нет рабочего времени`.

Нужно проверить фактический backend/frontend contract.

## Проверить

Какие данные являются источником рабочего времени:
- `hours_per_day`;
- per-day schedule;
- resource capacity record;
- WorkCenter schedule;
- другой существующий contract.

Проверить, что:
- вкладка `График`;
- readiness check;
- вкладка `Мощность`;
- Scheduler

читают один и тот же source of truth.

## Правило

`Рабочие дни` и `Рабочее время` — разные вещи.

Если заданы только:
Пн–Пт,

но нет количества часов:
ошибка должна быть более точной:

`Не указано количество рабочих часов`

а не создавать впечатление, что график полностью отсутствует.

Если `hours_per_day` в данных уже заполнен,
но UI показывает `—` или readiness всё равно выдаёт ошибку —
это frontend/backend contract defect, который нужно зафиксировать и минимально исправить в рамках допустимого scope.

Не подставлять 8/10 часов по умолчанию.

---

# 3. График должен быть самодостаточным

Вкладка `График` должна позволять пользователю понять:

- какие дни рабочие;
- сколько часов работы доступно;
- откуда взято это значение.

Минимально:

| | Пн | Вт | Ср | Чт | Пт | Сб | Вс |
|---|---|---|---|---|---|---|---|
| Работа | ✓ | ✓ | ✓ | ✓ | ✓ | – | – |
| Часы | 10 | 10 | 10 | 10 | 10 | – | – |

Если backend хранит одно `hours_per_day` для всех рабочих дней:
не создавать per-day модель.

UI может отображать одно значение по всем активным дням.

`Изменить график` должен редактировать существующие поля,
а не создавать дублирующий schedule.

---

# 4. Переименовать `Существующий ресурс`

Текущая подпись:

`Существующий ресурс`

непонятна пользователю.

Она может восприниматься как:
- существующая операция;
- существующее оборудование;
- существующая запись вообще.

Фактически это:
**уже созданный ресурс мощности, который можно связать с технологической операцией.**

## Новая терминология

Заменить label:

`Существующий ресурс`

на:

**`Привязать ресурс мощности`**

Placeholder:

**`Выберите ресурс мощности`**

Кнопка:

`Связать`

можно заменить на:

**`Привязать`**

Рядом при необходимости tooltip:

`Ресурс мощности — сотрудники, бригада или другой общий ресурс, используемый этой операцией при планировании.`

---

# 5. Не путать ресурс мощности и оборудование

На вкладке `Оборудование`:

- WorkCenter = физическая машина / оборудование;
- ресурс мощности = трудовой/бригадный/другой CapacityResource.

UI должен визуально разделять эти понятия.

Для equipment-driven операции:
не показывать дублирующий выбор той же машины в блоке `Привязать ресурс мощности`,
если WorkCenter уже является source of truth.

---

# 6. Убрать дублирование WorkCenter-полей

Дополнение по предыдущему замечанию владельца.

На вкладке `Оборудование` сейчас одновременно есть:
- список привязанного WorkCenter;
- поле выбора оборудования внутри resource edit;
- повторные capacity fields.

Для physical WorkCenter оставить один source of truth.

В operation modal:

### Оборудование
- список связанных WorkCenters;
- `Подключить оборудование`;
- `Изменить`;
- `Отвязать`.

Параметры конкретной машины:
- производительность;
- единица;
- hours;
- shifts;
- efficiency;
- working days

редактировать через WorkCenter quick-edit / существующий equipment contract.

Не показывать второй независимый `Оборудование *` selector для того же ресурса.

# 7. Readiness wording

Использовать понятные русские причины.

Предпочтительно:

- `Не указан ресурс мощности`
- `Не подключено оборудование`
- `Не указана производительность`
- `Не указано количество рабочих часов`
- `Не задан график работы`
- `Не задан способ расчёта`
- `Готово к планированию`

Не показывать пользователю внутренние:
- `missing_input`;
- `resource_capacity_not_configured`;
- `hours_per_day`;
- `explicit_hours`

как основной UI-текст.

Технический code допустим только в tooltip/debug details.

# 10. Backend gap rule

Если выяснится, что UI не может определить рабочее время,
