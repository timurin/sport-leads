# PC-04.4K PATCH — Tech Card Route UX Cleanup

## Исполнитель
Cursor

## Контекст
Текущая реализация функционально правильная, но интерфейс перегружен и плохо читается.

Не менять backend/runtime/Scheduler/ONE OF semantics.
Нужен только UX/UI patch standalone TechnicalCard.

## Главная цель
Сделать блок `Технологический процесс` компактным, понятным и визуально иерархичным:

`Маршрут → схема → вариант → прогноз → действие`

Без дублирующих кнопок, повторяющихся предупреждений и лишних технических деталей.

---

## 1. Убрать дублирование действий

Сейчас на экране несколько `Пересчитать план`.

Оставить одну основную кнопку:
`Пересчитать план`

Расположить её рядом с блоком прогноза/варианта.

Нижнюю дублирующую кнопку убрать.

`Сохранить даты` оставить рядом с полями дат, не смешивать с маршрутным UX.

---

## 2. Перестроить блок в 3 зоны

### A. Маршрут
Компактная строка:
- label `Маршрут производства`
- select
- status badge справа

Под select сразу короткая схема.

### B. Варианты
ONE OF group показывать рядом/под тем цехом, к которому относится группа.

Не делать отдельную большую карточку, оторванную от схемы.

Вместо этого:
- компактный блок `Способ раскроя`
- radio options
- badge `Предварительно` / `Подтверждено`
- button `Подтвердить`

### C. Прогноз
Отдельная компактная карточка:
- `Ожидаемая готовность`
- дата крупно
- `Дата отгрузки`
- `Запас / риск`
- recommendation если поддерживается

---

## 3. Схема маршрута

Сохранить цветную схему, но сделать компактнее:

- одинаковая высота Workshop blocks;
- меньше внутренних отступов;
- операции — компактные chips;
- стрелки по центру;
- ONE OF group внутри Workshop выделять мягким акцентом;
- selected option — solid accent;
- остальные — neutral;
- default — маленький secondary badge.

Не дублировать один и тот же selected option и в схеме, и отдельной большой карточкой одинаковым текстом.

---

## 4. ONE OF UX

Для группы `Способ раскроя`:

Показывать:

`Способ раскроя`
[○ Ручной] [● Настил] [○ Лазер]

или вертикально только на узких экранах.

Badge:
- `Предварительно`
- `Подтверждено`

Default пометка:
`по умолчанию`

Кнопки:
- если preliminary → `Подтвердить`
- если confirmed → без лишней кнопки
- change selection происходит сразу через radio/select по существующему API.

Не показывать отдельную кнопку `Изменить`, если выбор уже виден и доступен прямо в radio.

---

## 5. Прогноз до/после пересчёта

Сейчас `После пересчёта плана` выглядит как заглушка.

Сделать states:

### План не рассчитан
`Прогноз появится после расчёта плана`

CTA:
`Пересчитать план`

### План рассчитан
`Ожидаемая готовность`
`17.11.2026`

Под ним:
`Отгрузка 21.11.2026`
`Запас 4 дня`

Не показывать большой текст `После пересчёта плана`.

---

## 6. Recommendation

Если backend данных не даёт:
не оставлять пустое место.

Если recommendation есть:
показывать компактный callout:

`Рекомендуем: Лазер`
`Ожидаемая готовность на 2 дня раньше`

CTA:
`Выбрать`

Если recommendation нет:
секцию вообще не показывать.

---

## 7. Warning UX

Сейчас warning занимает слишком много места.

Сделать один компактный warning callout:

`Маршрут требует настройки`

Под ним:
`Не настроена производственная норма операции «...».`

Secondary:
`Настройку выполняет администратор производства.`

Не показывать raw technical code.

Не дублировать один и тот же warning в нескольких местах.

---

## 8. Поля плана

`Начало плана / Дата отгрузки / Приоритет / План заблокирован`

оставить отдельным компактным блоком ниже технологического процесса.

Не смешивать визуально с route selection.

---

## 9. Визуальная иерархия

Приоритет внимания:
1. маршрут;
2. выбранный ONE OF вариант;
3. ETA;
4. recommendation;
5. warning;
6. технические настройки плана.

Сделать меньше рамок и вложенных больших карточек.

Использовать:
- один основной контейнер;
- мягкие section backgrounds;
- меньше box borders;
- compact spacing;
- сильный accent только на selected/recommended/CTA.

---

## 10. Responsive

Desktop:
- схема в строку;
- ONE OF compact inline;
- ETA справа или под схемой.

Tablet:
- 2 колонки / wrap.

Mobile:
- вертикально.

Готово, если:
1. блок читается сверху вниз без повторов;
2. ONE OF выбор находится рядом с маршрутом, а не отдельной большой карточкой;
3. одна основная кнопка `Пересчитать план`;
4. ETA визуально главный результат;
5. warning компактный;
6. manager flow читается как `маршрут → вариант → прогноз → запуск/пересчёт`.
