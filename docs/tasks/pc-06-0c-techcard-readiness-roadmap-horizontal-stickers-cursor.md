# PC-06.0C — Techcard readiness roadmap: horizontal sticker layout (Cursor)

## Контекст
После PC-06.0B на карточке менеджера есть блок «Готовность техкарты». Логика и данные устраивают, но текущий вертикальный список занимает слишком много места и визуально тяжёлый.

## Цель
Сделать компактное горизонтальное представление roadmap в виде небольших стикеров/чипов, чтобы менеджер быстро видел статус шагов техкарты без длинного вертикального блока.

## Что сделать
1. Обновить только UI блока «Готовность техкарты» на странице техкарты.
2. Представить шаги readiness горизонтально, в виде компактных стикеров/чипов.
3. Каждый шаг должен показывать:
   - короткое название шага;
   - статус: completed / warning / blocked / current;
   - визуальный цветовой акцент без крупных карточек.
4. Стикеры должны располагаться в строку с переносом на новую строку при нехватке ширины.
5. Сохранить сверху компактную сводку:
   - общий статус;
   - прогресс вида «5 из 7»;
   - при необходимости короткий текст состояния.
6. По клику на стикер раскрывать/показывать снизу короткое описание:
   - что не заполнено;
   - как исправить;
   - ссылка/кнопка перехода, если она приходит из readiness.
7. Если шаг completed — описание можно не раскрывать автоматически, но оно должно быть доступно по клику.
8. На мобильной ширине блок должен остаться компактным: стикеры в несколько строк, без поломки вёрстки.

## Ограничения
- Не менять backend-контракт readiness.
- Не пересчитывать readiness на frontend.
- Не менять бизнес-логику запуска ТК.
- Не трогать другие блоки карточки, кроме визуального оформления readiness roadmap.
- Использовать существующий ответ `GET /technical-cards/{id}/readiness` как есть.

## Проверки
1. Проверить в браузере минимум 3 состояния:
   - черновик с блокирующими шагами;
   - карта почти готова;
   - завершённая карта.
2. Проверить desktop и mobile.
3. Прогнать frontend tests / eslint / tsc / `python scripts/check_project.py`.
4. `git diff --check` без ошибок.

## Критерии готовности
- Блок readiness roadmap отображается горизонтально и компактно.
- Шаги читаются как короткие стикеры, а не как длинный вертикальный список.
- По клику видно пояснение ошибки/действия по выбранному шагу.
- Визуально блок занимает заметно меньше вертикального места.
- Логика readiness и launch не сломана.
