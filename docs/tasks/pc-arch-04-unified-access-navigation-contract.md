# ARCH-04 — Unified Employees & Access Management: уточнение контракта

Статус: **согласовано как целевая концепция; глобальное UI-правило — только после проверки и отдельного утверждения**.

## Целевой результат ARCH-04

1. Единая точка управления сотрудниками и доступом: `/settings/employees`; карточка `/settings/employees/{id}`. `/settings/users` перестаёт быть самостоятельным местом администрирования, старые deep links сохраняют работоспособность.
2. В карточке сотрудника отдельная вкладка «Доступ к платформе». Кадровые данные принадлежат `Employee`, учётные данные и авторизация — `PlatformUser`.
3. Пользователь с серверным разрешением управлять доступом открывает **модальное окно** назначения прав. Матрица показывает только реальные разрешения backend.
4. Группы доступа имеют собственные права: «Менеджеры», «Дизайнеры» и др.; группа доступа не равна кадровой категории или должности.
5. Учётной записи можно назначить несколько групп; эффективные разрешения — объединение групп (аддитивная модель без deny/индивидуальных overrides в первом этапе). Существующие RBAC и admin должны сохраняться до согласованной миграции.

## NAV-04 — Контекстная модальная навигация (обязательно проверить в ARCH-04)

**Правило:** при переходе по ссылке/маршруту на связанную карточку, редактирование, настройку группы или матрицу доступа **из уже открытого рабочего экрана** целевой экран показывается в модальном слое, а не заменяет исходный экран. Закрытие возвращает к **точно тому экрану, с которого начался переход**: прежние вкладка, фильтры, поиск, прокрутка, выбранный сотрудник и несохранённый черновик остаются, если их сохранение безопасно.

- Поддержать вложенные переходы A → B → C: закрытие C возвращает B, закрытие B — A. Не дублировать модальные окна и не терять контекст.
- URL должен отражать выбранную сущность, чтобы работали Back/Forward и ссылки; при прямом открытии URL или обновлении страницы карточка корректно открывается как самостоятельная страница (без фиктивного фона и сломанного закрытия).
- Escape, крестик и Back закрывают соответствующий слой по правилам интерфейса. При несохранённых изменениях — подтверждение; фокус возвращается на инициатор перехода, при невозможности — на логичный элемент исходного экрана.
- Модальное окно должно быть доступно с клавиатуры, ограничивать фокус, поддерживать мобильный экран 320 px и не создавать горизонтальный скролл; вложенность ограничивать практическим UX, при необходимости заменять модальный уровень, сохраняя путь возврата.
- Авторизация, действия и серверные permissions проверяются независимо от способа открытия. Запрещено обходить RBAC через прямой URL.
- Не превращать **все** маршруты приложения автоматически в модальные: это целевой паттерн **контекстных переходов внутри рабочего процесса**, не для основного меню, логина и прямых ссылок. Расширение области применения — после UX/E2E и решения владельца.

## Приёмка до объявления глобальным правилом

1. Список сотрудников → карточка → вкладка «Доступ» → настройка группы/матрица → закрытие по шагам до исходного списка с сохранением фильтров и прокрутки.
2. Back/Forward, прямая ссылка, reload, Escape и закрытие по крестику ведут к предсказуемому результату.
3. Несохранённые изменения защищены; запись не происходит от закрытия.
4. 1440 / 768 / 390 / 320 px, клавиатура, фокус, управление несколькими слоями.
5. 403 и прямой URL не обходят доступ; регрессия существующих маршрутов и форм отсутствует.

После успешной проверки закрепить NAV-04 как глобальный UI-контракт в проектных правилах/`AGENTS.md` и `SL-UI-CONTEXT-v1.md`, **отдельным одобренным изменением**.
