# ARCH-04B — Employee ↔ PlatformUser: единая карточка (Cursor)

## Источник истины
Перед изменениями прочитай `AGENTS.md`, `docs/architecture/decisions/ADR-036-employee-platform-user-link.md`, `docs/architecture/employee-user-link-arch-04a.md`, отчёт `docs/tasks/pc-arch-04a-employee-user-link-codex.md` и текущие компоненты сотрудников/пользователей. Не предполагай имена API или поля — используй контракт ARCH-04A.

## Цель
Связать управление сотрудником и учётной записью в интерфейсе без дублирования карточек человека и без изменения RBAC.

## Объём
1. В карточке Employee показывай состояние доступа: нет учётной записи / привязана учётная запись, с переходом к существующему управлению доступом, если оно предусмотрено контрактом.
2. Обеспечь явную привязку существующего PlatformUser к Employee и отвязку через API ARCH-04A. Отображай последствия действия, запрашивай подтверждение отвязки. Не создавай несуществующие backend-операции.
3. Для связи разрешай только свободные аккаунты и свободных сотрудников; ошибки 403/404/409 и сетевые ошибки показывай без ложного успеха. Обновляй данные обеих поверхностей после успешной операции.
4. Чётко раздели HR-атрибуты Employee и атрибуты аутентификации/ролей PlatformUser. Не копируй ФИО или другие персональные поля между сущностями как второй источник истины.
5. При отсутствии нужного API для конкретного UX — зафиксируй блокер, не добавляй обходное дублирование данных.
6. Сохрани адаптивность интерфейса и клавиатурную доступность.

## Ограничения
- Не менять миграции, backend, RBAC, пароли, порядок авторизации, production-факты и уже существующие ID.
- Не делать автоматический backfill и не привязывать по совпадению имени/email.
- Не вводить новые категории сотрудников или новую модель ролей: категории и lifecycle — отдельное решение владельца.
- Не коммитить, не push и не deploy до ревью общей ARCH-04A+04B.
- Не затрагивать посторонние незакоммиченные изменения ARCH-04A.

## Проверки и отчёт
- Тесты: связанный/несвязанный сотрудник, успешная привязка/отвязка, подтверждение, конфликт UNIQUE, 403, сетевая ошибка, refresh на обеих поверхностях.
- Локальный browser smoke, включая 390px и клавиатуру; без модификации реальных производственных данных.
- `python scripts/check_project.py` (10/10) и `git diff --check`.
- Отчитайся о файлах, контрактах/API, выполненных проверках и открытых ограничениях. Обнови UI-контекст/документацию только при реальном изменении контракта.
