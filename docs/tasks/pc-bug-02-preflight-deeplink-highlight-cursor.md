# BUG-02 — Ошибки ТК: открыть точное поле (Cursor)

## Цель
Из `TechCardPreflightModal` действие на каждой исправимой ошибке должно приводить прямо к нужному месту: переключить вкладку/развернуть секцию или открыть существующее окно редактирования, подсветить конкретное поле, перевести туда фокус.

## Источники
`AGENTS.md`, `SL-UI-CONTEXT-v1` (UI-CALENDAR + модальные правила), `frontend/components/production/tech-card-preflight-modal.tsx`, `frontend/lib/production/tech-card-preflight.ts`, `tech-card-detail-workspace.tsx`, readiness `fix_url` / `fix_action`; уже реализованные PC-06.0E/F/G/H. Проверять действие реального `onOpen`, не ограничиваться unit тестом формирования подписи.

## Объём
- Для каждой ошибки с известной точкой исправления обеспечить последовательность: закрыть preflight → переключить правильный tab/section → дождаться mount → открыть требуемую edit-modal при необходимости → scroll into view → видимый highlight и focus.
- Для норм операции по возможности направить в соответствующую операцию/поле, для сборки — в параметры сборки, для даты/количества — в планирование. Если поле живёт в отдельном справочнике, использовать существующий route/deep-link и указать точное поле; не обещать невозможный inline editor.
- Highlight временный, не сохраняется в БД. Учитывать скрытые вкладки, scroll container, sticky header и modal focus trap. На ошибке не терять введённое пользователем.
- Недоступные/неисправимые автоматически ошибки показывают честное объяснение без фиктивной кнопки. Не дублировать readiness бизнес-правила на frontend.

## Проверки
Сценарии: required planning/date, модель, сборка, норма/метраж, отдельная технологическая операция, stale-plan. Проверить каждую кнопку с реальным click и видимым focused target, клавиатуру/Escape/return focus; 1440, 768, 390, 320 px; unit tests + `PROJECT CHECK 10/10`. Не менять backend/Scheduler и shell без нужды.

## Готово
Ни одна доступная кнопка «Исправить» не оставляет пользователя на прежнем месте без фокуса/подсветки. Отчёт: issue code → фактический target → пройденный E2E.
