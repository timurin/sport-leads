# BUG-03B — Контрагент ТК: выбрать/создать в модальном окне (Cursor)

Зависимость: сначала BUG-03A или его подтверждение действующего Client API.

## Цель
На экране создания ТК и в карточке ТК поле «Контрагент»: поиск и выбор существующего клиента, «Создать контрагента» в существующем модальном/create-drawer паттерне, сохранение ID через единый серверный путь. Новый клиент сразу доступен для выбора, без reload всей страницы.

## Работа
- Повторно использовать реальные Client list/create действия и общие формы/валидаторы платформы, не копировать локальную demo-базу или отдельный contractors CRUD.
- После create/choose сохранить `client_id` через подтверждённый BUG-03A путь (`SalesOrder` либо `TechnicalCardOrderGroup`), invalidate/revalidate все читающие поверхности. Строго показывать read-only/предупреждение, если изменение клиента затрагивает несколько ТК общей группы/заказа; подтверждать намерение пользователя, не переприсваивать незаметно.
- Источник для отображаемого имени — актуальный Client join по ID; после update в справочнике и reload устаревшее отображение недопустимо. Сохранить выбранный ID при ошибках сети и показать явную ошибку.
- Учитывать доступы на create/update client. Скрывать/отключать создание без прав; select остаётся доступен согласно существующей политике. Открытие окна не должно терять заполненную ТК.

## Проверки
Create ТК → выбрать Client → сохранить/reload; создать Client в модалке → авто-выбор; сменить Client в группе из нескольких ТК; изменить название в справочнике → reload/переход → актуальное имя; ошибки API, права, пустой список; keyboard/accessibility/responsive 1440/768/390/320; frontend tests, browser E2E, project10/10.

Без нового справочника/таблицы, перерисовки shell и изменений Scheduler.
