# Production Calendar v0.1 — Нагрузка отдела дизайна

**Статус:** СОГЛАСОВАНО ВЛАДЕЛЬЦЕМ, предварительная расчётная методика для внедрения.  
**Дата решения:** 2026-10-03  
**Область:** Sport-Leads / Производственный календарь / Отдел дизайна.  
**Сфера:** Планирование мощности; не изменение исходных техкарт, лекал или моделей.

## 1. Базовый принцип

Трудоёмкость дизайнера определяется **количеством самостоятельных дизайнов, уникальных размерных комплектов и деталей, которые вручную адаптируются к лекалам, а также финальной предпечатной подготовкой**. Общий тираж сам по себе не является линейным множителем. Повторяющиеся экземпляры одного подготовленного размера не увеличивают число задач подготовки файлов.

Текущий производственный процесс MOSMADE: размерный ряд вручную адаптируется дизайнером в CorelDRAW; автоматического дублирования и подгонки по лекалам пока нет.

Пример: 500 изделий в 5 размерах и 500 изделий в 12 размерах имеют разную трудоёмкость подготовки даже при равном тираже. Количество уникальных файлов/деталей определять по фактическому составу модели и способу экспорта, **без предположения, что один размер всегда равен одному файлу**.

## 2. Расчёт

Предварительная трудоёмкость (человеко-минуты):

    T_design = SUM(T_create_or_adapt_per_independent_design)
             + SUM(T_manual_adaptation_for_each_unique_size_and_required_piece)
             + T_final_check_export_handoff
             + T_nonstandard_extra_work

Человеко-часы = T_design / 60.

При отсутствии достоверной детализации применять ручную предварительную оценку времени; не подставлять нулевую норму и не утверждать точность. Значения нормативов на старте — **гипотезы**, которые нужно калибровать по факту, а не установленные стандарты MOSMADE.

## 3. Данные и ввод

- Самостоятельные дизайны/варианты, модели изделий, выбранные размеры и применимые детали — из заказа и существующей базы моделей/лекал, когда эти данные доступны.
- Тип работы: новый дизайн, адаптация готового, повторное использование без изменений.
- Способ подготовки: ручной (текущий), автоматизированный (возможное будущее расширение).
- Настраиваемые предварительные нормативы по типу работы, модели/детали и уникальному размеру.
- Планировщик может скорректировать итоговую оценку с указанием причины; исходные данные ТК, лекал и модели при этом не изменяются.
- Для отсутствующих входных данных показывать «нагрузка не рассчитана» либо явно маркировать ручную оценку.

## 4. Календарь и мощность

- Учёт загрузки в человеко-часах: сумма назначенной трудоёмкости на дату / доступные человеко-часы дизайнеров по графику смен и коэффициенту эффективности.
- Разрешено распределять работу по нескольким датам и вручную назначать часы при отсутствии норматива.
- Ожидание согласования заказчиком — календарная задержка/статус, **не занятость дизайнера**. Печать может оставаться заблокированной до выполнения необходимых условий согласования.
- План и факт хранить раздельно, не смешивать расчётную оценку с фактическими трудозатратами.

## 5. Изменяемость методики

Это **v0.1**, а не окончательная система нормирования. После начала работы собирать фактическое время по видам деятельности и уточнять нормативы, коэффициенты и гранулярность расчёта без изменения общего принципа календаря. В будущем для CorelDRAW-макроса предусмотреть отдельный способ подготовки с иными нормативами на автоматическую обработку и ручную проверку. Разработка макроса сейчас вне объёма.

## 6. Применение к UI-E / будущей реализации

До отдельной согласованной задачи Codex: **не менять действующие прототипы, backend/API/модели/миграции**. При последующей корректировке UI-E показать предлагаемую системой трудоёмкость в человеко-часах, её источник («расчёт / ручная оценка / нет нормы»), возможность обоснованной корректировки, распределение по датам и сравнение «было / станет».

**Решение владельца:** принцип согласован; после ввода системы в эксплуатацию расчётную логику можно уточнять по данным реального производства.

## 7. Документационное применение

- [Архитектура PC-02 §2.1](../architecture/production-calendar-pc-02.md) фиксирует состав человеко-минут, источники входов, снимок оценки, исключения и отделение ожидания согласования от занятости дизайнера.
- [Спецификация UI-E](../design/production-calendar/screens/manual-scheduling.md) и [общий UI-контракт](../design/production-calendar/ui-contract.md) отмечают прежние «3 минуты на изделие» только как условное значение уже созданного HTML. Оно не соответствует утверждённой методике дизайна и не является будущей нормой.
- Для отдельной будущей задачи остаются числовые гипотезы норм, правила определения уникальных комплектов/деталей, структура календарного снимка расчёта и источник условия согласования перед печатью для standalone ТК. Никакого обязательного `SalesOrder` или связи с `DesignProject` для такого плана не вводить по умолчанию.

В этой документационной итерации действующие HTML-прототипы, приложение, API, модели и миграции не изменялись. PC-UI-08, PC-02.1, PC-03 и общий `DESIGN-APPROVED` остаются в прежних состояниях.
