# PC-UI-05.1 — Увеличить модальное окно создания заказа

## Контекст
Прототип: `docs/design/production-calendar/create-order-prototype.html`. В текущем CSS `dialog` ограничен `width:min(760px, ...)`, `max-height:min(860px, ...)`, а `.dialog-body` имеет `max-height:calc(100vh - 185px); overflow-y:auto`. В результате даже на широком экране появляется неудобная внутренняя прокрутка. Используй существующие `AGENTS.md`, UI-контракт и дизайн SPORT UNIFORM; не меняй функциональную логику формы.

## Цель
Сделать модальное окно существенно шире и визуально компактнее, чтобы **на типовых desktop/laptop разрешениях все поля, снимок норматива, схема зависимостей и кнопки были одновременно видны без внутренней вертикальной прокрутки**.

## Микротаски
1. Переработать размеры `dialog` адаптивно: desktop ориентир `width:min(1120px, calc(100vw - 48px))`, с разумными пределами по высоте и безопасными отступами. Не создавать горизонтальный скролл.
2. Для экранов от ~1024 px использовать более плотную сетку формы (2–3 колонки по смыслу); номер/поиск ТК, изделие/модель/вариант, количество/маршрут/дата. Нельзя ухудшать читаемость и порядок перехода Tab.
3. Сгруппировать «Снимок модели и нагрузки» и «Календарные зависимости» **рядом на широких экранах**, а не двумя большими вертикальными блоками. Уменьшить избыточные отступы, сохранив читаемость.
4. Убрать внутренний `overflow-y:auto` у `.dialog-body` на desktop/laptop, если контент помещается. Не обрезать содержимое: адаптировать сетку и отступы, вместо скрытия полей.
5. На планшете 768–1023 px использовать подходящую сетку в 2 колонки; если высоты недостаточно — один предсказуемый режим прокрутки, не несколько вложенных скроллов.
6. На мобильных <=767 px оставить fullscreen-диалог. Физически весь контент не умещается на маленьком телефоне (особенно при экранной клавиатуре), поэтому допустить **одну вертикальную прокрутку контента fullscreen-диалога**, с закреплёнными шапкой и нижними кнопками; запретить горизонтальную прокрутку и вложенные независимые скроллы.
7. Обеспечить видимость сообщений валидации, предупреждения о просроченной дате, успешного состояния, клавиатурного фокуса и кнопок; проверить сценарий длинных названий ТК/модели.
8. Актуализировать `docs/design/production-calendar/screens/create-order.md` и UI-контракт. Не изменять статусы утверждения дизайна.

## Проверки и критерии готовности
- В Edge/Chromium проверить 1440×900, 1366×768, 1280×800, 1024×768, 768×1024, 390×844, 320×568; отдельно масштаб 125% на desktop, если возможно.
- На 1440×900 и 1366×768 **нет прокрутки внутри модального окна** и нет обрезанных блоков; все поля и footer видны одновременно.
- На 1024×768 максимально уместить без прокрутки; если это невозможно без ухудшения доступности, задокументировать точную причину и оставить единственный корректный скролл.
- На узких телефонах присутствует один рабочий вертикальный скролл; footer доступен, поля не перекрываются клавиатурой (по возможности проверить).
- Проверить Escape, Tab/Shift+Tab, возврат фокуса, валидацию, демосценарии, расчёт нормы; существующая логика данных неизменна.
- HTML, JS, визуальные скриншоты desktop и mobile, `git diff --check`; сообщить результаты и ограничения.

## Ограничения
Только автономный HTML-прототип UI-B и относящаяся к нему документация. Не изменять приложение Sport-Leads, API, модели, миграции, бизнес-правила и другие экраны. Не выставлять `DESIGN-APPROVED`. Сохранить незакоммиченные изменения; без commit/push. После выполнения остановиться для просмотра владельцем.
