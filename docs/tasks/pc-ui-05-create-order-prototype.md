# PC-UI-05 — UI-B: Быстрое добавление производственного заказа

## Контекст
UI-A — недельное табло Production Calendar v0.1 — подготовлено как базовый прототип, но общее утверждение дизайна ещё не получено. Использовать актуальные PC-01, PC-02, PC-02.1, UI-контракт, правила техкарт, моделей и маршрутов, SL-UI-BASE-v1 и дизайн-систему Sport-Leads. Не изменять приложение.

## Цель
Создать автономный адаптивный HTML-прототип модального окна по кнопке «Добавить заказ» из UI-A.

## Поля и правила
- **Номер заказа:** ручной, обязательный, без автогенерации. Учитывать вывод PC-02: номер принадлежит существующей группе standalone ТК; не создавать независимый дублирующий номер без документированного решения.
- **Номер техкарты:** поиск/выбор существующей standalone ТК по правилам платформы; не создавать дублирующий справочник.
- **Изделие:** ручное наименование, обязательно.
- **Модель:** поиск/выбор существующей модели и варианта сборки; исходные данные не менять.
- **Количество:** положительное целое число, обязательно.
- **Маршрут:** выбор по существующим правилам; линейный маршрут ТК не менять; зависимости календаря самостоятельны.
- **Плановая дата готовности:** ручной ввод с явным предупреждением, если дата прошла.

После выбора модели показывать модель, вариант сборки, наличие/отсутствие норматива, нормативное время на изделие и расчётную трудоёмкость заказа. Для нормативов использовать подтверждённые в PC-02.1 правила `duration_seconds`, кратность операций и снимок данных; не считать неопределённое время нулём. Отсутствие нормы не блокирует создание, отображается «Нагрузка не рассчитана».

Показывать компактную схему календарных зависимостей: Закупка и Дизайн — параллельно; после завершения обеих ветвей: Печать → Раскрой → Пошив → Упаковка. Не изменять маршрут ТК.

Кнопки «Отмена» и «Создать заказ». Создание только демонстрационное, без API и записи в приложение. После подтверждения показать сообщение «Заказ создан в календаре и ожидает распределения по датам». Не распределять заказ автоматически; планирование относится к UI-E.

## Состояния и UX
Проверить: пустая форма, заполненная форма, модель с нормой, модель без нормы, пустое обязательное поле, неверное количество, отсутствие маршрута, дата в прошлом, демонстрационное создание. Desktop — компактное модальное окно; mobile — почти fullscreen. Клавиатурная навигация, закрытие Escape, возврат фокуса на кнопку вызова. Использовать существующие визуальные компоненты и язык SPORT UNIFORM.
