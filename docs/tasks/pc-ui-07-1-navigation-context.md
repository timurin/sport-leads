# PC-UI-07.1 — Сохранение контекста навигации UI-A / UI-D / UI-C

## Контекст
UI-D (`section-day-prototype.html`) подготовлен. В нём формируются ссылки с `week`, `date`, `stage`, а при открытии UI-C — с `return`. Необходимо проверить и замкнуть весь маршрут во всех трёх **автономных прототипах**, а не только в UI-D. UI-B и другие экраны не переделывать.

## Цель
Переходы UI-A → UI-D → UI-C → UI-D → UI-A сохраняют выбранные неделю, дату и участок. Уход в UI-C из конкретной операции не должен выдавать демозаказ КД-041 за выбранный заказ с другим номером.

## Работы
1. Проверить, реально ли UI-A считывает параметры `week` и `stage` и применяет их к состоянию. При необходимости добавить безопасное чтение и валидацию параметров URL; значения по умолчанию оставить демонстрационными.
2. Обеспечить переход из ячейки UI-A в UI-D со значениями `date` и `stage` для выбранной ячейки (при сохранении доступного просмотра детализации, если это необходимо по UI-контракту).
3. Проверить UI-D: URL возврата к UI-A, ссылка из операции на UI-C, сохранение контекста даты и участка.
4. В UI-C обработать параметр `return` из UI-D только для разрешённого локального маршрута; обеспечить возврат к выбранной дате и участку. Из прямого входа в UI-C обычная ссылка ведёт в UI-A.
5. Для операций с номером, отличным от КД-041, явно оставить ссылку «Открыть демонстрационный пример КД-041» либо не делать перехода к чужой карточке; никаких ложных привязок.
6. Отразить контракт навигации в `navigation.md` / `ui-contract.md` и сценарии UI-D. PC-UI-07 оставить на приёмке владельца; общий DESIGN-APPROVED не устанавливать.

## Проверки и приёмка
- Edge: открытие UI-A с `?week=2026-10-05&stage=sewing` выставляет неделю и участок; переход из ячейки 2026-10-07 открывает UI-D на 7 октября и «Пошив».
- Из UI-D в UI-C и обратно возвращается выбранный день/участок, после чего UI-A открывает исходную неделю/фильтр.
- Прямые URL без query и некорректные параметры не ломают прототип.
- Desktop/mobile, клавиатура и существующие демосценарии не ухудшены.
- HTML/JS и `git diff --check` проходят.

Не изменять frontend/backend приложения, API, модели, миграции, DS-SHELL-01/02. Не выполнять commit/push. Остановиться для приёмки владельцем.
