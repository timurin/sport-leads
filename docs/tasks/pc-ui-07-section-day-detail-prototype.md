# PC-UI-07 — UI-D: Детализация загрузки участка за день

## Контекст и статус
- Production Calendar v0.1. PC-UI-05 (UI-B) и PC-UI-06 (UI-C) утверждены владельцем; UI-A используется как основной недельный экран. Зафиксировать `OWNER-APPROVED` для UI-C в Markdown roadmap и сгенерировать соответствующий HTML twin, не устанавливая **общий `DESIGN-APPROVED`**.
- Перед началом прочитать `AGENTS.md`, действующий roadmap, PC-01/PC-02/PC-02.1, `docs/design/production-calendar/ui-contract.md`, `navigation.md`, `screens/weekly-board.md`, `screens/production-order.md` и существующие UI-A/UI-B/UI-C HTML. Следовать действующим контрактам `DS-SHELL-01/02` и `SL-UI-BASE-v1`; без дублирования/переработки настоящего sidebar/topbar.
- Это **дизайн-прототип**, не разработка приложения. Все данные локальные демонстрационные.

## Цель
Создать автономный адаптивный single-file HTML **UI-D «Участок — день»**, который открывается по выбору ячейки недельного табло и позволяет диспетчеру оценить план участка на дату, список операций, доступные ресурсы и проблемы. Никаких фактических изменений статусов и сохранения данных.

## Микротаски

### PC-UI-07.1 — Контракт сценария
- Описать маршрут UI-A → UI-D → UI-C и возврат с сохранением контекста выбранных участка, даты и недели (в демо допустим query string / локальное JS-состояние, без новых API).
- Уточнить, что «закупка» — **ручная готовность материалов**, а не процент часовой загрузки без подтверждённой нормы.
- Создать спецификацию `docs/design/production-calendar/screens/section-day.md` с источниками полей, интеракциями и состояниями.

### PC-UI-07.2 — Шапка и метрики
- Заголовок «Пошив — 7 октября 2026» (дата и участок выбираются из демонстрационного набора); возврат «К календарю», стрелки предыдущий/следующий день, выбор участка.
- KPI: доступная мощность за день (человеко-часы), известный план (человеко-часы), загрузка %, резерв или превышение; количество назначенных операций.
- Чётко различать **перегрузку**, **блокировку запуска**, **отсутствие нормы**, **нулевую мощность** и **выходной**. Не выводить `0%` при неизвестных нормах; при частично неизвестном плане писать «Загрузка полностью не рассчитана», показывая отдельно известную часть.

### PC-UI-07.3 — Таблица операций
- Список по выбранному участку и дате: номер группы standalone ТК, техкарта, изделие, модель/вариант, плановое количество на день, норматив на изделие (где применим), известная трудоёмкость, статус календаря, блокирующие предшественники, действие «Подробнее».
- При нескольких заданиях одного участка показывать суммарную нагрузку по нормо-часам, а не складывать штуки разных моделей.
- «Подробнее» открывает read-only диалог операции; ссылка «Открыть карточку» ведёт на UI-C как демонстрационный сценарий. Не имитировать успешный фактический запуск, перенос или сохранение.
- Для планирования предусмотреть видимое действие «Распределить / Перенести» только как пояснение будущего UI-E (без фиктивного изменения данных).

### PC-UI-07.4 — Мощность и вычисления
- Отдельная демоконфигурация участка: количество доступных исполнителей по дате, часы смены, сменность, коэффициент эффективности (по умолчанию `1`), рабочие дни, исключения.
- Для **пошива** использовать снимок применимых строк варианта сборки: `sum(duration_seconds × multiplicity)` секунд на одно изделие одной швеёй; дневная нагрузка = норматив × запланированное на день количество / 3600; мощность = число швей × часы смены × смены × эффективность. Вычисления строго в одинаковых единицах.
- Для остальных участков не выдавать неподтверждённую трудоёмкость из модели; показывать либо явно помеченную ручную оценку демо, либо «Норма не задана». Закупку считать через ручной статус готовности.
- Проверить демонстрационные случаи нормы, 100%-ной загрузки, >100%-ной перегрузки, недостаточных данных и нулевого числа работников.

### PC-UI-07.5 — Компоновка и адаптивность
- Desktop/laptop: шапка + KPI, основная таблица операций и компактная боковая/нижняя панель «Мощность и ограничения». Не создавать бессмысленный почасовой график, в котором нормо-часы нескольких швей ошибочно выдаются за часы календарного времени.
- Tablet/mobile: карточки операций вместо широкой таблицы, доступные кнопки, без горизонтального скролла всей страницы; проверить 1440×900, 1366×768, 1024×768, 768×1024, 390×844 и 320×568.
- Диалоги: Tab/Shift+Tab, Escape, возврат фокуса, понятные `aria-label`; не допускать потери кнопок за внутренней прокруткой.

### PC-UI-07.6 — Состояния и проверки
- Демо-переключатели: нормальная загрузка, перегрузка, заблокированная операция при свободной мощности, отсутствует норматив, нулевая мощность, выходной с назначением, пустой день, закупка/готовность.
- Проверить HTML, синтаксис JS, расчёты, фильтры/переключение даты, детализацию, адаптивность и `git diff --check`. Браузерную проверку и скриншоты desktop/mobile выполнить при доступности Edge; в противном случае явно отметить отсутствие визуальной проверки.
- Обновить `ui-contract.md`, `navigation.md`, соответствующие Markdown roadmap и HTML twin по правилам репозитория; **PC-UI-07 оставить открытым до решения владельца**. В отчёте перечислить изменённые файлы, проверки, известные ограничения.

## Приёмка
1. UI-C отмечен `OWNER-APPROVED` на основании решения владельца; общий `DESIGN-APPROVED` не установлен.
2. UI-D показывает понятную реальную величину загрузки участка и операции на выбранный день.
3. Перегрузка, ожидание предшественников и недостаток норм не смешиваются.
4. Есть удобные переходы из UI-A и в UI-C; демонстрационные действия не притворяются сохранёнными.
5. Есть отчёт проверок и прототип предоставлен для визуального решения владельца. Остановиться.
