# PC-UI-09.1 — Проверка ограничений ресурсов UI-F

**Статус:** выполнено; после проверки UI-F OWNER-APPROVED владельцем согласно [задаче PC-UI-10/11](pc-ui-10-11-gantt-risks-autonomous-v01.md). Общий DESIGN-APPROVED остаётся открытым.

Контекст: UI-F (`docs/design/production-calendar/capacity-settings-prototype.html`) готов к приёмке. Требуются две локальные поправки без смены дизайна. Следовать `AGENTS.md` и утверждённому контракту `docs/architecture/production-calendar-capacity-v0.1.md`.

## Задача
1. Валидация суточной мощности **одной машины**: `часы смены × число смен ≤ 24` (с учётом базовых настроек и исключений типа override); не допускать 3 × 10 = 30 машино-часов/сутки. Проверить также режим ручной доступности: не более 24 часов на одну машину в дату. Не применять ограничение 24 ко всему пулу сотрудников (его человеко-часы могут быть >24).
2. Развести причины недоступности по типу ресурса: «Ремонт оборудования» только для `machine`; для `staff` и `team` — «Нерабочий день / отсутствие персонала». Если используется единое внутреннее состояние unavailable, сохранить корректную пользовательскую подпись и контракт без дублирования сущностей.
3. Предпросмотр «До → после», сообщения об ошибках и демосценарии должны соответствовать правилам; недопустимые настройки нельзя применять. Проверить смену выбранного ресурса и корректность отображения исключений.
4. Уточнить спецификацию `docs/design/production-calendar/screens/capacity-settings.md` и `ui-contract.md` только там, где необходимо. Не менять утверждённые нормы MOSMADE и остальные экраны.

## Проверка и завершение
- Проверить сценарии: машина 10×3 (отказ), машина 8×3 (допустимо), ручная мощность машины 25 ч (отказ), пул двух работников 2×10×2 = 40 чел.-ч (не блокировать только из-за >24), ремонт оборудования и отсутствие сотрудника; desktop 1366 и mobile 390.
- Проверить HTML/JS и `git diff --check`; по возможности зафиксировать результаты браузерной проверки.
- Только автономный прототип и связанная документация; никаких изменений frontend/backend/API/моделей/миграций. Без commit/push.
- `OWNER-APPROVED` UI-F и общий `DESIGN-APPROVED` не устанавливать; остановиться для проверки владельцем.
