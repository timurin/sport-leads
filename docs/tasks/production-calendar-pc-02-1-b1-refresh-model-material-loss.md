## Причина и граница исправления

В `backend/app/services/technical_cards.py::refresh_model_and_pattern_composition` комментарий обещает сохранять материалы/заметки. Однако `_sync_materials_to_composition(..., model_changed=True)` при отсутствии BOM вызывает `_clear_material_composition_lines`; маршрут не создаёт замену. В итоге ручная/спецификационная строка материала исчезает. Следует исправить контракт владения строками состава при обновлении модели: отделить обновляемые строки из BOM/маршрута от пользовательских/применённых строк, не удалять последние молча. Первичная регистрация была read-only; отдельная задача исправления выполнена 2026-10-05, без изменения схемы/API.

## Регрессионные сценарии для отдельного исправления

1. Модель без BOM и без маршрутных материалов: применение Spec `MATERIAL` + `NOTE`, затем refresh той же модели сохраняет обе строки и актуализирует `PATTERN`.
2. Ручной `MATERIAL` через `PUT composition` при модели без BOM переживает refresh той же модели; порядок и плановое количество не меняются без действия пользователя.
3. Повторный refresh идемпотентен: не удаляет ручные строки и не дублирует автоматически созданные.
4. При наличии BOM/маршрутных материалов обновляются только строки, которыми владеет соответствующий источник; для конфликтов с ручными/Spec строками требуется явный контракт до реализации исправления.
5. При реальной смене модели правило обработки старых исходных материалов документировано отдельно и проверено; данные не исчезают незаметно.
6. Refresh не пишет в Spec, PO, складской ledger и не меняет факт исполнения ТК. Проверить соседние тесты состава/маршрута.

**Критерий закрытия B1:** минимальное исправление сервиса и сфокусированные регрессионные тесты проходят вместе с применимыми проверками проекта; согласован сценарий смены модели. Критерий подтверждён 2026-10-05 регрессиями refresh; baseline DB/lint сбои учитываются отдельно. PC-03 не запускать автоматически.

## Влияние на календарь и закупку

**Результат исправления 2026-10-05:** refresh обновляет заголовок и лекала, не вызывает повторный префилл материалов/плановых норм. Ручные, Spec и route MATERIAL сохраняют id, привязки, порядок, план/факт/единицы/notes; повторный refresh не создаёт дубли. Создание/восстановление ТК и явная замена состава/привязка другой модели сохраняют прежний контракт (ADR-035). Проверки: 13 targeted passed; backend без теста подключения к БД 467 passed / 1 skipped; полный check 7/10 — локальная роль PostgreSQL `sport_leads` отсутствует, прежние 3 frontend lint errors. Подробности: `pc-02-1-b1-fix-refresh-model-material-loss.md`. B1 закрыт; PC-03 не начат.

Норматив пошива календарь читает из строк выбранного варианта сборки, поэтому этот дефект не меняет `duration_seconds` и сумму нормо-секунд напрямую. Состав ТК может потерять строку материала; следовательно, календарь **не вправе** выводить «Закупка завершена» из наличия/отсутствия материала в ТК, Spec, PO или складе. Подтверждение закупки остаётся отдельным ручным календарным событием с автором, временем и основанием. Оно не подтверждает фактическое поступление или полноту материалов; если состав ТК расходится с источниками, показывать предупреждение и дать диспетчеру проверить основание, без автоматического сброса или проставления статуса.
