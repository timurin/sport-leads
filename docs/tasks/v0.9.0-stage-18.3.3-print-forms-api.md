# Stage 18.3.3 - print-form registry API

## Scope

Next unfinished roadmap item after `18.3.2`.

Deliver backend service and HTTP API for the Administration print-form registry:

- list / get registry entries;
- create and update metadata with stable binding keys;
- activate and archive entries through explicit lifecycle actions;
- guard writes with a dedicated platform permission;
- add focused backend regression tests.

Out of scope for this slice:

- template content upload/editor flow;
- preview/render pipeline;
- Administration UI;
- consumer print output integration.

## Acceptance

1. `GET /print-forms` returns persisted registry entries without demo fallback.
2. `POST /print-forms` and `PATCH /print-forms/{id}` persist metadata and validate binding rules.
3. Activation is explicit and fails if no current published version exists.
4. Archive is explicit and does not delete history.
5. Focused backend tests cover CRUD, lifecycle, validation, and permission gates.
