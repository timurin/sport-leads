# Stage 18.3.4 - print-form storage, preview, and generation pipeline

## Scope

Next unfinished roadmap item after `18.3.3`.

Deliver backend pipeline pieces needed before Administration UI:

- version CRUD for print-form templates;
- explicit publish/current workflow for template versions;
- preview endpoint that renders a selected or current template with payload data;
- registry generation endpoint that resolves an active print form by binding and renders it;
- focused backend regression tests.

## Constraints

- No parallel template store in sales or technical-card modules.
- No hidden fallback when an active print form or published current version is missing.
- Runtime stays registry-driven: `binding_type + binding_key + output_format`.
- Rendering MVP is text-template based for `inline_text` storage and produces JSON preview/generate results for the next UI and consumer slices.

## Acceptance

1. Versions can be created, updated, and published under one print-form registry entry.
2. Only one current version is maintained by the service when publish/current flags change.
3. Preview renders template placeholders from payload data without mutating business documents.
4. Generate resolves the active registry entry and current published version by binding lookup.
5. Focused backend tests cover publish/current, preview, and generate paths.
