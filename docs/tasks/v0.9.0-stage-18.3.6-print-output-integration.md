# Stage 18.3.6 - Sales print output integration

## Scope

Next unfinished roadmap item after `18.3.5`.

Wire the sales consumer side to the Stage `18.3` print-form registry without introducing a parallel template store:

- sales order documents panel uses `POST /print-forms/generate`;
- print entry points for `sales_order`, `sales_quotation`, `sales_invoice`;
- payload is prepared by the sales module from existing order / quotation / invoice snapshots;
- missing active form fails explicitly in UI.

## Constraints

- No new backend domain or template storage in Sales.
- No shell visual changes; only the order documents panel in the Stage `3.3.3` contour.
- Use stable registry binding keys, not route-based resolution.
- No demo fallback when a print form is not configured.

## Visual checklist

1. `/sales/orders/[id]` → panel `Документы` shows print actions for order / quotation / invoice.
2. `Печать заказа` generates output through the registry.
3. `Печать КП` is enabled only when a quotation exists and opens/generated output.
4. `Печать счёта` is enabled only when an invoice exists and opens/generated output.
5. If no active print form is configured, the panel shows an explicit error message from API.
