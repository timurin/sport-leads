## Goal

After model (+ assembly variant), the order item picks a `ShopRoutingTemplate` from the **product model routing whitelist only** (`6.1.17`) — not the global routing catalog. Snapshot `routing_template_id` + name on `SalesOrderItem` for TC generate; catalog edits do not rewrite old orders. Mirrors assembly-variant selection (`3.2.5`).

Selection chain (locked):

```
Nomenclature (PRODUCT)
  → ProductModel ∈ available-models whitelist
      → AssemblyVariant ∈ active variants of that model
          → ShopRoutingTemplate ∈ model routing whitelist (6.1.17)
```

## Snapshot fields

| Field | Role |
|-------|------|
| `routing_template_id` | Live FK → `shop_routing_templates.id`, nullable, `ON DELETE SET NULL` |
| `routing_template_name` | Immutable display snapshot of template name at selection time |

Server-authoritative fill on select/change. Client-supplied name must not override when an id is present. Clearing/changing model clears or revalidates routing; catalog renames do not mutate stored snapshots.

## API / UI notes

**Service rules (mirror `3.2.5` assembly):**

| Model routing whitelist | Rule |
|-------------------------|------|
| Empty (0 active links) | `routing_template_id` optional |
| ≥1 active link | `routing_template_id` **required** and ∈ that model’s whitelist |
| Any | Routing not on selected model’s whitelist → reject |
| New selection | Inactive template / inactive link cannot be newly selected |
| TC generate | Prefer order-item routing snapshot over model `default_routing_template_id` alone |

**UI (`3.2.7.3`):**

- Routing select appears **after** model (and alongside / after assembly variant as in the locked chain)
- Hidden when no model is selected
- Options = active links from model whitelist only (`6.1.17`) — do **not** load full `/shop-routings` catalog as the picker source
- Soft-optional when whitelist is non-empty is forbidden
