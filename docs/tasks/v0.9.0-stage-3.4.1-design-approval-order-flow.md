# Task — 3.4.1 Design and approval states in order flow

**Roadmap:** `3.4.1.1`–`3.4.1.6`  
**Date:** `2026-07-31`  
**ADR:** ADR-003 amend (+ Stage 10 boundary)

## Goal

На заказе — **sales-side** статус согласования дизайна и гейт перед `production`. Полные макеты / клиентский review — Stage **10** (не дублировать).

## Boundary

| In `3.4.1` | Out (Stage 10 / other) |
|------------|-------------------------|
| `SalesOrder.design_approval_status` | Design project, versions, layouts, comments (`10.1`) |
| Gate `→ production` | Client review UI / correction requests (`10.2`) |
| Order card control | Shop цех Дизайн (`11.4`) |

## Contract

### Status enum

| Value | Meaning |
|-------|---------|
| `not_required` | Дизайн не нужен / не контролируется (default MVP) |
| `pending` | Ожидает передачи в согласование |
| `in_review` | На согласовании у клиента |
| `approved` | Согласовано — можно в производство |
| `rejected` | Отклонено — производство запрещено |

### Gate

Transition **to** `SalesOrderStatus.production` allowed only when:

`design_approval_status ∈ { not_required, approved }`

Other transitions unchanged. Stage 10 later may set `in_review` / `approved` / `rejected` from approval workflow; until then managers set status on the order card.

### API

- Field on `SalesOrderRead`: `design_approval_status`
- `PATCH /orders/{id}/design-approval` body `{ "design_approval_status": "…" }`
