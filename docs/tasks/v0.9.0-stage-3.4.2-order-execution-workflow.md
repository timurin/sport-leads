## Contract

### Payment

| Value | Meaning |
|-------|---------|
| `unpaid` | `paid_amount = 0` (default) |
| `partial` | `0 < paid_amount < order.amount` (or amount null and paid_amount > 0) |
| `paid` | `paid_amount >= order.amount` when amount set; or explicit full mark |

`paid_amount`: `Numeric(14,2) >= 0`. PATCH may send `paid_amount` and/or `payment_status`; amount wins for derivation when both present.

### Material reserve (sales flag)

| Value | Meaning |
|-------|---------|
| `not_required` | Резерв не контролируется (default) |
| `pending` | Нужен резерв / ожидает |
| `reserved` | Менеджер отметил резерв (без складского документа) |

Informational only in MVP — **no** hard gate on `production`.

### Closure gate

Transition **to** `SalesOrderStatus.completed` allowed only when:

`payment_status == paid`

(+ existing manufacturing-completeness gate from `9.5`).

### API

- Fields on `SalesOrderRead`: `payment_status`, `paid_amount`, `material_reserve_status`
- `PATCH /orders/{id}/payment` body `{ "paid_amount"?, "payment_status"? }`
- `PATCH /orders/{id}/material-reserve` body `{ "material_reserve_status": "…" }`
