## Goal

1. **Folder tree** — `/settings/catalogs/sewing_operations` as parent/child **folders** with leaf `SewingOperation` rows (not flat A→Z / not flat order-only strip).  
2. **Templates library** — named packs of ordered catalog sewing-operation refs.  
3. **Apply** — apply template → assembly variant (copy-on-pick snapshot, as `6.3.6`).

## Contract

### 6.3.11 — Folder tree catalog

| Rule | Detail |
|------|--------|
| Folder entity | `SewingOperationFolder`: `id`, `name`, nullable `parent_id`, sibling `sort_order ≥ 0` |
| Nesting | Folders may nest; cycle-safe parent changes (exclude descendants) |
| Operation placement | `SewingOperation.folder_id` nullable = root; sibling `sort_order` among ops in same folder |
| List/tree order | Within parent: folders then ops (or interleaved by `sort_order` — fix in domain `6.3.11.1`); default sibling order |
| Backfill | Existing ops → root; `sort_order` by current `lower(name)` |
| UI | Collapsible tree: create folder/child, rename, move op into folder, ↑/↓ siblings; pattern like `nomenclature-category-folder-tree` / owner visual `4.9.5` |
| Pickers | Assembly (`6.3.6`) / templates (`6.3.12`) select **leaf operations only** — folders are not snapshot targets |
| Out | Soft `is_active` on **operations**; DnD-only without persisted parent/`sort_order`; PatternSet revival |

**Amendment vs first draft:** flat catalog `sort_order` alone is **insufficient**; hierarchy is required.

### 6.3.12 — Templates library

| Rule | Detail |
|------|--------|
| Entities | `SewingOperationTemplate` + `SewingOperationTemplateLine` |
| Line | `template_id`, `sewing_operation_id`, `sequence` (≥1, unique per template) |
| Name | Template `name` globally unique (trim, non-empty) |
| Snapshot on template | **No** — lines reference live catalog ops |
| Snapshot on apply | Yes — only in `6.3.13` → `AssemblyOperationLine` |
| Route | Modal on `/settings/catalogs/sewing_operations` (no separate nav); legacy templates path redirects |
| Shell | `DS-SHELL-01` / `DS-SHELL-02` preserved (nav only via `navigation.ts`) |

### 6.3.13 — Apply to assembly variant

| Rule | Detail |
|------|--------|
| Effect | Copy-on-pick lines: `operation_name`, `cost`, `quantity_per_item`, `duration_seconds`, `sewing_operation_id` + `sequence` |
| Default mode | **Append** to end of existing variant lines (confirm) |
| Replace mode | API flag + UI confirm dialog |
| Equipment | **Do not** copy `work_center_ids` (same as `6.3.10`) |
| Catalog drift | Later catalog/template/folder edits do not rewrite existing variant lines |

## Boundaries

| Concept | Relation |
|---------|----------|
| `SewingOperationFolder` | Navigation container (parent/child); not priced; not copied to assembly |
| `SewingOperation` | Leaf cost/time catalog atom; may sit in a folder or at root |
| `SewingOperationTemplate` | Named ordered pack of catalog op refs (library) |
| `AssemblyVariant` / `AssemblyOperationLine` | Per-model commercial recipe; snapshots on pick/apply |
| Stage 8 `TechOperation` | Shop volume/units — **not** this contour |
| Nomenclature categories | UX/reference pattern only — separate table/API |
