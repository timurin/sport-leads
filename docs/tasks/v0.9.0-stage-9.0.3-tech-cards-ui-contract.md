## Confirmed contract

### 1. List — `/production/tech-cards` (PT-02)

**Columns (MVP):**

| Column | Source (planned) |
|--------|------------------|
| № ТК | `{orderNo}-{cardSeq}` |
| Заказ | EntityLink → `/sales/orders/{id}` |
| Позиция | nomenclature snapshot / line label |
| Модель | model snapshot / link when available |
| Статус | status badge |
| Участок | current routing stage label |
| Кол-во | qty; optional `done/total` unit-lines when API ready |
| Обновлено | `updated_at` |

**Empty / error:** shared `EmptyState` + segment `error.tsx`; **no demo rows**, no silent fixture substitution.

**Row open:** navigates to `/production/tech-cards/[id]`.

### 2. Filters

**MVP (required for first list build):**

- статус
- заказ (`orderId` query + search/select)
- участок (stage) — bind labels when Stage 8 routing exists; until then enum/placeholder from ADR-016 without fake stages

**Deferred (optional later, do not block MVP list):**

- период `updated_at`
- «мои» / open-only chips

**Deep-link:** `?orderId=` prefilters list (`9.4.1.2`). Clear filter restores unscoped list.

### 3. Toolbar (list)

Icon cluster order (align with catalog toolbar discipline):

1. Search  
2. Reset search  
3. Filter (popover: MVP filters)  
4. Reset filter  
5. Print (selection mode; print output may stub until `18.3` / tech-card A4×2 `18.3.8`)

**End action:** primary **«Сформировать из заказа»** — uses real generate API (`9.2.1`) when ready; until API exists the button is present but must show explicit API/empty error (no demo generate). Prefer `orderId` context when list is prefiltered; otherwise order picker.

Do **not** use blank «+ Создать» for orphan tech cards without an order line (one card per manufacturable `SalesOrderItem`).

### 4. Document header (PT-07)

- Back: list; secondary back/link to source order when known  
- Title: № ТК + short nomenclature/model label  
- Status badge + current stage  
- Meta: заказ (EntityLink), order line, qty, dates; performer when known  
- Actions: open order; stage complete / rollback (role-gated later); print stub OK until print registry (`18.3.8` for A4×2)

### 5. Document body (PT-07)

Ordered blocks (SectionCards):

1. **Состав** — model, patterns, materials / planned composition (Spec version when Stage 7 ready), assembly-variant snapshot ref; optional design mockup link (Stage 10 when ready)  
2. **Поштучно** — unit-lines table, N = order line qty (size, personalization, number, …); bulk edit hooks later  
3. **Операции / объёмы** — TechOperation snapshot rows: operation name, volume, unit (`linear_meters` | `pieces`), stage binding (`9.3.3`; catalog `8.1.3`)  
4. **Маршрут / участки** — stage timeline + results (performer, timestamps, scrap/rework); strict gates (`9.2.2.2`)  
5. **История** — `ActivityTimeline` when events exist  

Completeness hint when sibling cards on the same order are not all terminal (`9.5`) — summary only; gate logic stays in services.

Print layout Side1/Side2 A4 consumes the same domain fields via `18.3.8` (Excel = print visual SoT; not a parallel PT-07 layout).

### 6. Settings — `/settings/catalogs/tech-cards`

Owned by Stage **`9.6`**, not Stage 18 directories.

**MVP settings blocks:**

- eligible nomenclature types for ТК generation  
- numbering template (`{orderNo}-{cardSeq}` default)  
- default unit-line field set  
- stage display labels bound to Stage 8 routing templates (no duplicate shop-routing editor)  
- **not** TechOperation CRUD (catalog owned by Stage `8.1.3`)

UI: PT-02-CATALOG list or single settings card (PT-05) if one document — decide in `9.6.1` without changing this surface route.

### 7. Order card (gap `#4`)

Only via `9.4.1`: per-line link + status; generate; open filtered production list. No parallel Stage 3 tech-card module.
