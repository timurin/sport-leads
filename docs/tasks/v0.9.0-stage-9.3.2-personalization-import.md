# Task — 9.3.2.5–9.3.2.8 aggregate personalization import

**Roadmap:** `9.3.2.5`–`9.3.2.8`  
**Date:** `2026-07-28`  
**ADR:** ADR-016 §2 amend (`2026-07-28`)

## Goal

Keep technical-card unit lines as SoT (`N = order quantity`), but allow managers to import personalization in **aggregate** rows by columns and expand them into per-piece unit lines.

## Owner decisions

- Import format is aggregate, not per-piece
- Columns: `size_type`, `size`, `surname`, `print_number`, `quantity`, `notes`
- `surname` maps to `personalization`
- `print_number` stays a separate text field
- `color` is removed from active UI/import; legacy nullable storage may remain until cleanup
- `Σ quantity` of import rows must equal the order-item quantity exactly

## Microtasks

- [ ] `9.3.2.5` — Amend domain/UI contract: `size_type` + visible fields without `color`
- [ ] `9.3.2.6` — Backend aggregate import endpoint/service: validate sum and expand into N unit lines
- [ ] `9.3.2.7` — Frontend «Поштучно»: aggregate import UX and updated visible columns
- [ ] `9.3.2.8` — Regression tests for expand, reject, and round-trip

## Expected API shape

Aggregate import request rows:

| Field | Meaning |
|-------|---------|
| `size_type` | `male` / `female` |
| `size` | Display size |
| `personalization` | Surname / name text |
| `print_number` | Number text |
| `quantity` | Aggregate count for this combination |
| `notes` | Optional note applied to each expanded unit row |

Rules:

- `Σ quantity == unit_line_count_from_quantity(order_item.quantity)`
- service expands each aggregate row into `quantity` unit lines
- resulting `unit_index` sequence is `1..N`
- import replaces the active unit-line matrix for the card

## Out of scope

- Replacing unit lines as SoT with aggregate storage
- Full settings-driven field configurator (`9.6`)
- Stage 18 print matrix implementation

## Acceptance

- [ ] Aggregate import expands into N stored unit lines
- [ ] Quantity mismatch is rejected with a clear domain error
- [ ] UI no longer shows `color` in active personalization columns
- [ ] `size_type` round-trips through API and UI
