## Schema changes

Composition MATERIAL lines (extend existing composition row model from `9.3.1`):

| Field | Type / notes |
|-------|----------------|
| `production_stage_id` | FK → ProductionStage (цех bind); required for MATERIAL in this stage |
| `planned_qty` | Decimal/Numeric; replaces legacy `quantity` |
| `fact_qty` | Decimal/Numeric, nullable until shop writes |

Migration:

- Rename / copy legacy `quantity` → `planned_qty`
- Add `fact_qty` (nullable)
- Add `production_stage_id` (nullable for non-MATERIAL lines; MATERIAL binds to цех)
- Upgrade + downgrade required

Locked semantics:

- Manager adds MATERIAL and binds to цех (`production_stage_id`)
- `planned_qty` = hint from `ProductModelOperationNorm` × order qty (not hard BOM SoT; sizes may differ)
- `fact_qty` written by shop on stage path; manager MVP = read-only for fact

## Gate rules

| ProductionStage | Code | Material hard-gate MVP |
|-----------------|------|------------------------|
| Раскрой | `cutting` | **Yes** — cannot `complete` while any MATERIAL with this `production_stage_id` lacks `fact_qty` |
| Печать | `print` | **Yes** — same rule |
| Other цеха | (any other) | **No** — no material hard-gate in MVP |

Hook: stage complete path from `9.2.2`. Reject with a clear domain error (do not soft-pass or hide).

## API notes

| Concern | Direction |
|---------|-----------|
| Composition read | Expose `planned_qty`, `fact_qty`, `production_stage_id` on MATERIAL lines |
| Composition write (manager) | MATERIAL: nomenclature + `production_stage_id` + `planned_qty`; **do not** accept manager writes to `fact_qty` in MVP |
| Prefill | On generate / material add: compute `planned_qty` hint from norms × order-line qty when binding known |
| Stage complete | Enforce cutting/print hard gate before status flip |
| Shop fact write | Dedicated shop path later (`11.5` / `11.6`); this stage may stub or expose a narrow internal write for tests — manager UI stays fact read-only |

Reuse existing composition endpoints where possible (`PUT /technical-cards/{id}/composition` and related); extend schemas rather than inventing a parallel composition model.
