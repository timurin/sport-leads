# 9.5.1 — Manufacturing completeness on sales order

Roadmap: `docs/roadmap/roadmap.md` § `9.5.1`  
ADR: `docs/architecture/decisions/ADR-016-technical-card-domain.md` §4

## Goal

Backend SoT for «заказ производственно полон по ТК»; gate commercial status transitions that mean production-complete (`ready` / `shipped` / `completed`) until every eligible line has a **completed** technical card. Document integration points for unfinished Stage `3.4.2` (reserve / payment / shipping docs).

## Scope

### In

- Service `compute_order_manufacturing_completeness` (ADR-016: eligible PRODUCT lines; cancelled/missing block; vacuous true when no eligible lines).
- `GET /orders/{id}/manufacturing-completeness`.
- Status gate in `update_sales_order_status` for `ready` / `shipped` / `completed`.
- Regression tests + docs checkpoint.

### Out

- Full Stage `3.4.2` reserve/payment/shipping document workflow (reuse helper when that stage ships).
- Replacing commercial `SalesOrder.status` with TC status.
- Owner visual on order strip (already `9.4.1`; optional live API later).

## Microtasks

- [x] 9.5.1.1 — Service: compute order manufacturing completeness from technical cards
- [x] 9.5.1.2 — Integrate with order execution workflow (status READY+ gates; document 3.4.2 hook)
- [x] 9.5.1.3 — Documentation and regression tests

## Integration with Stage 3.4.2

| Gate | Rule (MVP `9.5`) |
|------|------------------|
| `new` → `confirmed` / `production` | No TC completeness required |
| `*` → `ready` / `shipped` / `completed` | Requires `manufacturing_complete` |
| `*` → `cancelled` | No TC gate |
| Future reserve / ship docs | Call `require_manufacturing_complete_for_status` (or completeness read) before posting movements that assume finished goods |

Commercial stage rail is **not** overwritten by TC status (ADR-016).
