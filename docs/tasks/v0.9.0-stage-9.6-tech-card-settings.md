## Contract (`9.6.1`)

Settings under `/settings/catalogs/tech-cards` own only:

1. Eligible nomenclature types for technical-card generation.
2. Numbering template defaults; MVP default remains `{orderNo}-{cardSeq}`.
3. Default active fields for unit lines/import (`size_type`, `size`, `personalization`, `print_number`, `notes`, later extensions).
4. Stage-label binding policy: display label is a snapshot/presentation field; execution gates stay on `production_stage_id`.

## Explicitly not here

- TechOperation CRUD / required-material editing (`8.1.3` / `8.1.4`)
- Shop routing CRUD (`8.2`)
- Production-stage catalog CRUD (`8.3`)
- Shop-floor execution forms (`11.3`–`11.10`)
- Auth/roles (`17.1`)

## Notes

- The existing Settings landing page already links to `/settings/catalogs/tech-cards`; this stage fills the actual contour behind that entry.
- Any future eligible-type extension must preserve the base invariant `1 technical card = 1 sales order line`.
