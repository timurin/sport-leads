## 1.4.3.1 Contract (closed)

### Two registries (do not merge)

| Registry | Owns | Product of | SoT entity |
|----------|------|------------|------------|
| **A. Source collectors** (`1.4.1`, extend in `1.4.3.2`) | Pull/push **ingest** of external *prospect / form / calendar* payloads into CRM | `CollectorFactory` + new types (e.g. `webhook_form`) | Ultimately **`Lead`** (+ contact); sport calendar path may still land in `SportEvent` first |
| **B. Communication connectors** (`1.4.2`, real in `1.4.3.3`) | Send/receive **messages** on a channel (email / VK / Telegram / …) | `ConnectorRegistry` + `CommunicationService` | **`LeadMessage`** (CRM); never `CollaborationMessage` |

Rules:

1. Do **not** put HTTP form ingest into `ConnectorRegistry` just because both are “integrations”.
2. Do **not** put Telegram send into `CollectorFactory`.
3. Shared **transport helpers** (HTTP client, signature verify, retry) may live under a thin shared package later (`16.1`); CRM mapping stays owned by **1.4.3**.

### Lead-source ingest mapping (`1.4.3.2`)

Normalized CRM ingest DTO (name TBD in implement; conceptual fields):

| Normalized field | Maps to |
|------------------|---------|
| contact name / phone / email | `Lead` + `LeadContact` (create or match by phone/email when present) |
| company / org hint | optional Client/Organization link later (`2.3`+); MVP may store on lead commercial/text fields only |
| source label / channel code | `Lead.source` (or existing source field) + ingest audit metadata |
| free text / comment | lead description / first note — **not** Stage 19 chat |
| external id | idempotency key (unique per adapter); duplicate ingest → no second Lead |

Flow:

```text
Webhook/HTTP → adapter.normalize → CRM ingest service → create_lead / update contacts
                                         ↘ LeadEvent (source=adapter)
```

- Prefer reuse of `create_lead` validation; do not invent a parallel Lead model.
- Sport-event collectors remain valid for **calendar** contour; CRM form webhook is a **new** collector/adapter type that targets `Lead`, not a fork of `SportEvent` schema.
- Contour **C** (ADR-020): not catalog Excel (A), not TC inline (B), not 1C jobs (D).

### Communication adapter mapping (`1.4.3.3`)

| Direction | Path |
|-----------|------|
| Outbound (lead card send) | UI → `POST /leads/{id}/messages` → bridge to `CommunicationService.send` → connector → persist `LeadMessage` with real `external_id`, `is_mock=false` when connector is non-mock |
| Inbound webhook | connector `normalize_webhook` → resolve `lead_id` (metadata / conversation map) → persist inbound `LeadMessage` |

- Replace mock-only write in `create_lead_message` for channels that have a registered real connector; mock remains fallback / test.
- `CommunicationChannel.INTERNAL` stays forbidden on external connectors (already in `CommunicationService`).
- Phone channel: no text send (existing rule); voice later out of MVP.

### ≠ Stage 19 (hard boundary)

| | CRM `1.4.3` / `1.2.4` | Stage `19` |
|--|----------------------|-----------|
| Entity | `LeadMessage` on **Lead** | `CollaborationMessage` on **SalesOrder** (+ optional TC) |
| Audience | Client / external channel | Staff only |
| Connectors | Email/VK/Telegram/… | None (in-app) |
| UI | Lead card communications | Order «Коммуникация» / TC panel |

Forbidden: routing external CRM messages into `CollaborationThread`, or using Stage 19 as lead outbound transport.

| Concern | Owner |

### Credentials (`1.4.3.4` preview)

- Persist connector config in DB (or settings) with **secrets outside git** (env / host secret store).
- No API keys in repo or frontend bundles.
- Admin surface: minimal enable/disable + channel credentials under Administration or CRM settings (exact route in implement).

- Full multi-tenant connector marketplace.
- Replacing sport-event collectors for calendar import.
