# Task — 2.3.1 Client legal requisites and bank accounts

**Roadmap:** `2.3.1.1`–`2.3.1.4` (`SL-ROADMAP-v1.00`)  
**Date:** `2026-08-23`  
**Contract code:** `SL-CLIENT-REQUISITES-v1`

## Host

Client card `/sales/clients/[clientId]` (`DS-PT-05`).  
Do **not** put `bank_accounts[]` or address blobs on `GET /clients` list DTO (`SL-LIST-PAGE-RULES-v1`).

## Client fields (nullable)

| Field | Rule |
|-------|------|
| `inn` | 10 or 12 digits (RU INN) |
| `kpp` | 9 digits if set — **included** (optional, approved here) |
| `ogrn` | 13 or 15 digits if set — **included** (optional, approved here) |
| `legal_address` | max 500 |
| `actual_address` | max 500 |

Blank string → `null`. Not synced to `Organization` in this item (`2.4` owns org card).

## Bank accounts

Child table `ClientBankAccount` (`client_id` CASCADE).

| Field | Rule |
|-------|------|
| `bank_name` | required, max 255 |
| `bik` | 9 digits |
| `account_number` | 20 digits |
| `corr_account` | 20 digits or null |
| `is_primary` | one primary per client (first account becomes primary) |
| `sort_order` | `≥ 0` |

## API

`GET /clients/{id}` adds the five fields + `bank_accounts` (not on list).

`PATCH /clients/{id}` — `ClientUpdate` (`exclude_unset`): `folder_id` and/or requisites. Empty patch → 422.

| Method | Path |
|--------|------|
| `POST` | `/clients/{id}/bank-accounts` |
| `PATCH` | `/clients/{id}/bank-accounts/{account_id}` |
| `DELETE` | `/clients/{id}/bank-accounts/{account_id}` |

404 missing client/account. 422 invalid digits / empty patch.

## UI

Editable «Юр. реквизиты» + table of accounts on the card. Empty state, no demo.
