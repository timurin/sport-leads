## SoT

| Layer | Role |
|-------|------|
| **Stage 14.2** (`14.2.1` / `14.2.2`) | Future **ledger** SoT: invoices, payments, advances, debt, settlements by order and client |
| **`3.4.2` on `SalesOrder`** | Current **sales markers**: `payment_status`, `paid_amount`, commercial `amount` |
| **`2.3.3` MVP** | **Read-only projection** of those markers onto the client card. Not a second ledger. No `Client.balance` / settlement table / fake postings |

When Stage 14 ships, this API is replaced or rewired to the ledger. Until then the UI must label the block as a **summary from order payment markers**, not as a bank/ledger balance.

## Host

`/sales/clients/[clientId]` (`DS-PT-05`), after legal + segments, before history.  
Do **not** put settlement fields on `GET /clients` list DTO (`SL-LIST-PAGE-RULES-v1`).

## Included orders

`SalesOrder.client_id = client` **and** `status != cancelled`.

Cancelled orders are excluded from all money and open-order counts.

## Formulas (`Decimal`, RUB MVP `3.3.3`)

Let `due(o) = max(amount − paid_amount, 0)` and `over(o) = max(paid_amount − amount, 0)` when `amount` is not null.

| Field | Rule |
|-------|------|
| `open_order_count` | `status ∉ {cancelled, completed}` |
| `open_order_amount` | Σ `amount` of those open orders (`amount` null skipped in the sum, still counted) |
| `receivable` (долг) | Σ `due(o)` for included orders with `amount` set |
| `advance` (переплата) | Σ `over(o)` for included orders with `amount` set |
| `paid_total` | Σ `paid_amount` for included orders |
| `orders_without_amount_count` | included orders with `amount is null` (shown so we do not invent debt) |

`amount` null: do **not** invent receivable. Order still counts toward `open_order_count` if status is open.

No per-row fetch on the client card: one summary GET.

## API (`2.3.3.2`)

`GET /clients/{client_id}/settlements-summary` → 404 if client missing.

JSON (names stable for FE):

```json
{
  "currency_code": "RUB",
  "open_order_count": 0,
  "open_order_amount": "0.00",
  "receivable": "0.00",
  "advance": "0.00",
  "paid_total": "0.00",
  "orders_without_amount_count": 0,
  "source": "sales_order_payment_markers",
  "ledger_stage": "14.2"
}
```

Money fields: string Decimal (same as other sales DTOs). Empty client: zeros, not demo.

Show the four money figures + open count. No PATCH. No fake “оплатить” from this block.

## Out of scope

- Payment ledger / advances as documents (`14.2`)
- Shipping docs (`14.1`)
- Writing `paid_amount` (stays on order card `PATCH /orders/{id}/payment`)
- List-column debt (`GET /clients`)
- Employee / org finance
- Multi-currency aggregation (orders stay RUB MVP; if a non-RUB order appears later, exclude it from sums and count in a warning field — **not** in this MVP; all current orders are RUB)
