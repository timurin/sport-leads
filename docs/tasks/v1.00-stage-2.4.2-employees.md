## SoT

Persistent `Employee` (`backend/app/models/sales.py`) is the only SoT for **org HR people**: contacts, job title, free-text department, employment date, belonging to an `Organization`.

| Not SoT | Why |
|---------|-----|
| `employeeRecords` / `employeesDefinition` | Demo `EntityWorkspace` path — **drop** |
| `PlatformUser` / `/settings/users` | Login, roles, invite — Stage **21** / `17.1` |
| `SalesUser` | CRM responsible on leads/orders — not HR |
| Stage 24 sewer | Sewer = `PlatformUser`; ≠ Employee |
| `PlatformUser.department` / `position` | Readable labels on the login cabinet; not HR SoT |

`platform_user_id` (soft Employee↔login link) is **out of this MVP**. Do not add the column or UI. `2.4.2.4` explicitly defers auth linkage to `17.1` / Stage 21.

## API

| Method | Path | Notes |
|--------|------|-------|
| `GET` | `/employees?active_only=true` | default **true** (pickers later). Settings list uses `false`. Optional `organization_id`, `q`. |
| `GET` | `/employees/{id}` | 404 if missing |
| `POST` | `/employees` | 201; `full_name` + `organization_id` required; missing org → 422 |
| `PATCH` | `/employees/{id}` | `exclude_unset`; empty patch → 422 |

No DELETE. Archive via `is_active=false`.

Do **not** change `GET /organizations` default `active_only`. Do not merge with `/platform-users`.

## UI

- Drop `employeeRecords`. Empty API list = empty state, not demo.
- List columns: ФИО, должность, подразделение, организация, телефон, статус. Row → card.
- Create drawer: ФИО + организация (active orgs) + должность + подразделение + телефон. Rest on card.
- Card: all writable fields above; no login/roles/pay/tasks tabs.
- No silent demo substitution on load error.
- Create is blocked with a message if there are no active organizations.
