### Decision per field

Policy for `20.1.2`: **hide from this commercial UI** (edit + view). Do **not** DROP columns in `20.1.2` (no data loss; historical leads keep values). Hard column retirement → optional later microtask outside `20.1` if owner confirms unused.

| Field | UI commercial block | DB / API | Rationale |
|-------|---------------------|----------|-----------|
| `product_type` | **hide** | **retain** | Not copied on convert; freeform string ≠ catalog `ProductType`. Safe to stop editing here. |
| `kit_quantity` | **hide** | **retain** | Not on `SalesOrder`; convert uses `estimated_quantity` for `quantity`. |
| `estimated_amount` | **hide** from commercial block | **retain** | Convert fallback: `SalesOrder.amount ← lead.estimated_amount` ([`lead_conversion.py`](backend/app/services/lead_conversion.py)). Also used on lead list/metrics. SoT stays; do not delete write path on `LeadUpdate` / commercial save API — only stop exposing in this form (API may still accept for backfill/scripts). |
| `size_comment` | **hide** | **retain** | Not on order; size SoT lives on order lines later. |
| `desired_date` | **hide** from commercial block | **retain** | Convert: `SalesOrder.desired_date ← lead.desired_date`. Keep column; convert dialog may still set/override. |
| `event_date` | **hide** | **retain** | Not mapped to `SalesOrder`; only UI/validation warning vs ready date. |

**Forbidden in `20.1.2`:** dropping columns; clearing existing values en masse; changing convert mapping for `estimated_amount` / `desired_date` without a dedicated task.

### Fields that stay in commercial block (unchanged by `20.1`)

Examples still in scope of the same component (not exhaustive): direction, sport, product category, need description, estimated quantity, preliminary budget, discount %, probability, planned order date, delivery_*, source/campaign/utm, priority.

### Convert / order impact

```text
Lead.estimated_amount ──convert──► SalesOrder.amount
Lead.desired_date     ──convert──► SalesOrder.desired_date
Lead.estimated_quantity ──convert──► SalesOrder.quantity
Lead.product_category / sport / source / need_description ──convert──► order fields
```

| Removed from commercial UI | Convert impact |
|----------------------------|----------------|
| product_type, kit_quantity, size_comment, event_date | None today |
| estimated_amount, desired_date | SoT retained; values already stored remain available to convert; new leads may leave them null unless set elsewhere (convert payload / future UI) |

- Sync set = **fields that remain visible on lead commercial** after `20.1.2`, plus convert-critical retained SoT (`estimated_amount` / `desired_date`) if order card exposes equivalents.

- Order already has `desired_date`, `amount`, `quantity`, `product_category`, `sport`, `description` — parity maps those, not `product_type` / `kit_quantity` / `size_comment` / `event_date`.
