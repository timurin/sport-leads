## Domain (`24.0.2`) — take / reserve / complete / release

### Commands

| API intent | Status in | Status out |
|------------|-----------|------------|
| take | (new row) | `reserved` |
| complete («отшить») | `reserved` | `completed` |
| release («отказаться») | `reserved` | `released` |

No DELETE. Snapshot `unit_price` immutable after take.

### Kinds and remaining pools (independent)

| kind | Planned cap | Busy = Σ qty where status ∈ {reserved, completed} |
|------|-------------|----------------------|
| `piece` | unit-line count on the TC | ledger rows `kind=piece` on that TC |
| `operation` | that sewing `TechnicalCardOperationLine.volume` | ledger rows on that operation line id |

Take **409** if `qty` > remaining. Released qty returns to the pool.

`11.7` fact does **not** subtract from the pool (no numeric piece qty on stage result).

Take allowed only while TC **current** routing stage is Пошив (`code=sewing`). Queue in the cabinet = those TCs. No QR in this stage.

### Price snapshot (at take)

- `operation` → live `SewingOperation.cost`
- `piece` → `TechnicalCard.assembly_variant_total_cost` (per item); reject take if null

Earnings for a period: Σ `qty * unit_price` of **completed** rows in range. No personal rate table.
