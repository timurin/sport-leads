## Domain (`25.0.2`)

### QR

One cryptographically random / UUID token per `TechnicalCard`. Print on `18.3.8`. Resolve by token only. No session-less public scan.

### Actor / цех

Session user. Allowed = **current or next** of selected unit lines ∩ `17.1.2.8` (role_fallback as shop). Several → picker. Skip forbidden. Sewing commands also need `sewing_cabinet.write`. No new permission codes.

### Commands (option C: route + fact)

| Command | Effect |
|---------|--------|
| accept | selected units in work on current цех |
| complete_transfer | shop fact required; units → next |
| return | units → previous; partial set allowed |

Partial = subset of unit lines (each line = 1 piece).

### Location

Live `production_stage_id` on the unit line + `last_transfer_kind` (`accept` / `forward` / `return`). No child TCs.

### Status (computed, not a second kanban SoT)

1. Any live unit still on `return` → **возврат**
2. Else ship-readiness of live units (`ready_to_ship` / `shipped`): all → **готова**; some → **частично готова**; none → **в работе**

### FG (`12.3.2`)

Post qty = unit lines arriving at the FG stage. Multiple docs per TC OK. Do not post the rest of the card. Idempotent per piece.

### Sewing

Scan writes Stage 24 ledger with the same pools. After split WIP, cabinet queue = cards with live units on Пошив.
