## Problem

Shared sewing operation names live in the catalog (`/settings/catalogs/sewing_operations`), but **cost / quantity / duration** differ per product model. Today economics sit on `SewingOperation` and are copied on pick — managers cannot edit per-model values without duplicating catalog entries.

## Contract (`SL-SEWING-OPS-ECONOMICS-v1`)

### Domain shift

| Layer | Before | After |
|-------|--------|-------|
| `SewingOperation` (catalog leaf) | name + cost + qty + duration + folder + equipment | name + **description** (≤256) + folder + equipment |
| `AssemblyOperationLine` (model variant) | snapshot from catalog on pick; read-only in UI | **SoT** for cost / qty / duration; **editable** on model card |
| Pick defaults | copy catalog economics | cost=`0`, qty=`1`, duration=`0` — manager edits on model |
| Sewing cabinet `unit_price` (`operation` kind) | `SewingOperation.cost` | assembly **snapshot** cost for the TC sewing op line (order-item snapshot or live variant line) |

### Catalog UI (`/settings/catalogs/sewing_operations`)

Columns: **Операция** | **Описание** | **Оборудование** | actions.

Remove: Стоимость, Кол-во, Сумма, Время.

Create/import drawers: same — add **Описание** (max 256 chars); drop numeric fields.

### Model assembly UI (`/settings/catalogs/product-models/[id]`)

Expanded variant table:

| Операция | Кол-во | Цена | Время | Сумма | delete |
|----------|--------|------|-------|-------|--------|

- **Кол-во / Цена / Время** — inline editable (`PATCH …/operation-lines/{id}`; API exists in `product_models.py`).
- **Время** = `duration_seconds` per operation (not × qty in the cell; variant header total time stays computed).
- **Сумма** = read-only `cost × quantity_per_item`.

Pick drawer (add ops from catalog): show **name + description** only — no catalog totals.

### Pick defaults (`assembly_variants.py` `_append_sewing_operation_lines`)

When appending from catalog:

- `cost` = `0`
- `quantity_per_item` = `1`
- `duration_seconds` = `0`

Still snapshot `operation_name` + optional `sewing_operation_id`.

### Unchanged surfaces

| Surface | Rule |
|---------|------|
| `SalesOrderItemAssemblyOperationSnapshot` | Shape unchanged; still copies from variant lines on item select |
| TC sewing sync (`_sync_sewing_operation_lines`) | Unchanged; still copies names + `sewing_operation_id` |
| Existing `AssemblyOperationLine` rows | **Keep** stored cost/qty/time after catalog column drop (no mass backfill required) |
| `SewingOperationTemplate` lines | Still only `sewing_operation_id` + sequence; economics come from variant on apply |

### Sewing cabinet (`sewing_cabinet.py`)

For ledger lines with kind `operation`, resolve `unit_price` from:

1. Order-item assembly snapshot matching TC sewing op line, or
2. Live `AssemblyOperationLine` on the variant linked to the TC

**Not** from `SewingOperation.cost` after this stage.
